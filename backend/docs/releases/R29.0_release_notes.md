# Release R29.0 — DB-first Positions default + staleness guardrail

**Date:** 2026-03  
**NO GIT.** Manual-only.

**Goal:** Positions page defaults to "Source: Stored" (DB read). When stored data is stale, show a safe-label banner and "Rebuild unified positions" action. No background jobs; manual-only.

---

## User-visible changes

- **Positions page:**
  - **Default source** is now **Stored** (source=db when no query param). Explicit toggle: "Stored" / "Computed".
  - When viewing **Stored** and data is **stale** (rebuild never run or last rebuild >6h ago): prominent banner "Stored positions may be stale — Review" with subtext and button **"Rebuild unified positions"**. Confirm modal; button disabled while rebuild runs (shows "Rebuild running").
  - When viewing **Computed**, no staleness banner (computed is authoritative).

## API / system-health contract

- **GET /api/ui/system-health** — **positions_unified_rebuild** block now includes **finished_at_utc** (alias of last_rebuild_at_utc) for frontend staleness (6h threshold). **last_include_paper** remains. Safe labels only; no FAIL/WARN/PASS.
- No change to GET /api/ui/positions/unified or GET /api/ui/positions/unified/db behavior.

## Determinism and safe labels

- Staleness computed client-side from positions_unified_rebuild.finished_at_utc. All labels in banner and button are safe (Review, Rebuild running). No FAIL/WARN/PASS in API or DOM.
- Rebuild mutation invalidates system-health, stored positions, computed positions, reconcile-diff.
