# R23.4.5 — Targets/Exit Plan Validity + S/R Selection Hardening + Universe Shares Consistency

**Goal:** Fix target selection so T1/T2/T3 are monotonic and meaningful; harden S/R selection with minimum distance; ensure Universe Shares column uses the same request-time compute path as Symbol Diagnostics Shares tab.

---

## Acceptance criteria

### 1. Targets/Exit Plan validity

- For any symbol with spot:
  - **Upside targets strictly increasing:** T1 < T2 < T3 (CSP). For CC: T1 > T2 > T3.
  - **Stop direction:** Stop below entry/spot for long/CSP; for CC stop above.
  - **Resistance at or below spot:** If nearest resistance ≤ spot (or within epsilon), do not use it; use next higher resistance or ATR fallback.
  - **Support at or above spot:** If nearest support ≥ spot (or within epsilon), do not use it; use next lower support or ATR fallback.
- **Response fields:** `target_basis` ("SR_LEVEL" | "ATR_FALLBACK"), `level_source_timeframe` (daily/weekly/monthly when SR used), `distance_to_t1_pct`. If distance_to_t1_pct < 0.10% treat as junk (UI can show badge).

### 2. S/R selection hardening

- Request-time S/R as ordered lists: `supports_ordered`, `resistances_ordered` per timeframe (level, distance_pct).
- Config: `MIN_TARGET_DISTANCE_PCT` = 0.20%, `TARGET_EPS_PCT` = 0.10%. If no level meets threshold, use ATR fallback.
- Single `support_level` / `resistance_level` represent the chosen actionable level.

### 3. Universe Shares consistency

- `/api/ui/universe` uses the same `compute_shares_eligibility(symbol=..., technicals, symbol_eligibility, mtf_levels)` path as Symbol Diagnostics Shares tab.
- When shares_eligible is true, Universe Shares column shows ELIGIBLE.
- Regression test: universe `shares_eligible` matches symbol-diagnostics `shares_plan.eligible` (e.g. artifact with empty diagnostics).

### 4. UI (lightweight)

- Tooltips: bar_count ("candles sampled for this timeframe S/R"), hold-time ("estimated sessions for price to travel 1 ATR toward T1, heuristic"), target_basis ("SR level used" vs "ATR fallback").
- When targets already exceeded at render: badge "Target already exceeded (price above T1)"; backend recomputes using next resistance or ATR (no reordering in UI).

---

## Non-negotiables

- No changes to decision artifact persistence format; request-time only.
- No raw FAIL_/WARN_ strings in UI.
- All changes covered with tests + docs + verification; gates recorded.
