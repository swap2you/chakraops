# R26.9 — Execution discipline lock (Ticket → Journal → Notifications → EOD)

**Branch:** release/R26.9  
**Manual-only.** No broker automation.

## Objectives

- Ops execution log (SQLite) to record overrides and done transitions without polluting the trade journal.
- TodayPage queue: Mark Done only when journal saved for that ticket OR skip reason recorded.
- EOD checklist: block mark-done when NEW notifications exist unless override reason provided.
- Safe UI: no FAIL/WARN; deterministic rules.

## Non-negotiables

- Decision artifacts remain code-only; no prose/UI strings persisted; no raw FAIL_/WARN_ in decision_latest.json.
- UI safe labels only; no FAIL/WARN words.
- Determinism: rules deterministic for same inputs (journal rows + ops log + notifications state).
- No broker automation.
- Gates must pass; evidence in out/verification/R26.9/notes.md + UAT checklist.

## Scope

### 1) Ops execution log (SQLite under DATA_DIR)

- **Store:** `app/core/ops/execution_log_store_r269.py`
- **Table:** execution_log — id, ts, symbol, strategy, action, ticket_id, event_type, reason (≤140 chars)
- **event_type:** "MARK_DONE" | "SKIP_JOURNAL" | "EOD_OVERRIDE"
- **API:** POST /api/ui/ops/execution-log (write event); GET /api/ui/ops/execution-log?date=YYYY-MM-DD (optional debug)

### 2) TodayPage queue behavior (frontend)

- Queue item: ticket_id, symbol, strategy, action, created_ts, status ("OPEN"|"DONE"), done_ts, journal_saved (bool)
- Mark Done: if matching journal entry exists for today (symbol + strategy + same day), allow. Else require "Skip journal" modal → POST execution-log SKIP_JOURNAL + MARK_DONE → then mark done.
- When "Save to Journal" succeeds from Ticket page: set queue item journal_saved=true for same ticket_id (localStorage + optional event).

### 3) EOD Checklist enforcement (backend + UI)

- EOD mark-done: if NEW notifications count > 0, reject 409 unless override_reason provided. If override_reason, write execution_log EOD_OVERRIDE and allow.
- UI: show "Cannot complete EOD while inbox has NEW items." and optional override reason input.

### 4) UI safe

- Badges: "Journal saved", "Skipped (reason recorded)". No FAIL/WARN.

### 5) Tests

- Backend: test_r269_execution_discipline.py (log write/read, EOD 409 when NEW, EOD with override, no FAIL_/WARN_ in API).
- Frontend: TodayPage queue gate, skip modal, EOD blocked when notifications_new_count > 0, no FAIL/WARN in DOM.
