# R28.8 — Reconcile Diff v1 (read-only, operator explainability)

**NO GIT.** Manual-only. No broker automation.

## Goal

When reconcile shows "Review", the operator can see **what** is mismatched (missing in unified, extra in unified, key field mismatch) without inspecting SQLite manually. Read-only; no writes; safe labels only.

## Non-negotiables

- No decision artifact writes. No notifications. No unified DB mutation.
- No raw FAIL/WARN/PASS in API payloads, runtime state, or UI.
- Deterministic output ordering (symbol, type, position_id).

## Scope

### A) Backend

- **GET /api/ui/positions/unified/reconcile-diff**
  - Query params: include_paper (default true), symbol (optional), limit (default 200).
  - Response: status, status_label, missing_count, extra_count, mismatched_count, items (list of { kind, id, symbol, instrument_type, is_paper, fields_diff? }).
  - Diff: compare authoritative sources vs unified DB (open positions). Missing = in source, not in unified; extra = in unified, not in source; mismatched = same id, qty/type/strike/expiry/opened_ts differ.
  - Deterministic sort by (symbol, instrument_type, id). Apply limit to combined items.

### B) Frontend

- SystemDiagnosticsPage: "Unified Positions Reconcile Diff" card with summary counts (missing, extra, mismatched), "View details" expand/collapse, link from diff row to /positions?symbol=X&include_paper=true. No FAIL/WARN/PASS in DOM.

### C) Tests

- Backend: deterministic ordering; filters (symbol, include_paper, limit); no forbidden tokens in payload; no decision_latest write.
- Frontend: diff card renders; View details toggles; document has no /\b(FAIL|WARN|PASS)\b/.

### D) Docs + Verification

- out/verification/R28.8/notes.md with gate tails, UAT, grep proof.
