# R24.2 — Lifecycle Alerts + Richer Actionable Details + Dashboard Workflow

**Date:** 2026-02

## What changed

- **Lifecycle evaluation (request-time only):** Actionable items now include structured lifecycle state: severity (high/medium/low), and for options: expiry, strike, dte, size, notional, pct_max_profit when available. next_action remains a safe label (ENTRY/HOLD/CLOSE/ROLL/NONE). next_action_details and lifecycle fields are computed at request time and never persisted in decision artifacts.

- **Lifecycle rules:** PROFIT_TARGET_HIT (target reached → CLOSE), ROLL_WINDOW (low DTE → ROLL), stop/risk breach → CLOSE. Shares use existing shares_plan and exit_plan for target/stop. Conservative defaults only.

- **API:** GET `/api/ui/action-needed` extended: each item includes `severity`; options items may include `expiry`, `strike`, `dte`, `size`, `notional`, `pct_max_profit`, `recommended_by`. No FAIL_/WARN_ in response.

- **Slack:** Actionable message includes contract-specific fields (symbol, strategy, expiry, strike, dte, premium/size, next action, rationale). Dedupe unchanged. Sanitization unchanged.

- **Dashboard:** Action Needed sorted by severity (high first); severity indicator shown; enriched details (e.g. DTE, strike) displayed. Deep link to symbol tab/accordion unchanged. Safe labels only.

## Endpoints

- **GET /api/ui/action-needed** — Same as R24.1; response items extended with `severity`; options items with optional `expiry`, `strike`, `dte`, `size`, `notional`, `pct_max_profit`, `recommended_by`. Backward compatible.

## UI behavior

- Dashboard Action Needed: rows sorted by severity (high then medium then low); optional severity badge or section; key numbers and rationale as before; link to symbol-diagnostics with tab and accordion.

## Risk / guardrails

- No new persistence of prose or raw codes. All new fields are either derived from existing store data at request time or constants (e.g. recommended_by).
- Determinism: lifecycle and next_action use same snapshot and store; no non-deterministic logic added.

## Migration / compat

- None. Existing clients of action-needed can ignore new fields. Frontend consumes new fields for display and sort order.

## Known limits

- pct_max_profit and current_price_proxy for options may be omitted when quote/data not available.
- recommended_by is a fixed ruleset version string (e.g. "r242"); no versioning DB.
