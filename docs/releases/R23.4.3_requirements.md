# R23.4.3 — Copilot key parsing + clear operator diagnostics

## Objectives

- Resolve operator confusion when Copilot returns COPILOT_AUTH_FAILED (OpenAI 401): clarify which env vars to set, that keys can be quoted/whitespace-trimmed, and surface key source and last error in system health.
- Keep Copilot read-only; never log or expose secrets; no persistence of Copilot output in decision artifacts.

## Scope

### 1. Robust API key parsing (backend)

- **`_clean_api_key(v: str | None) -> str | None)`** in `chakraops/app/api/copilot.py`:
  - Return `None` if `v` is `None`.
  - Strip whitespace; remove surrounding single or double quotes (`"..."` or `'...'`); strip again.
  - Return `None` if empty after cleaning.
- **`_get_copilot_api_key()`**: read COPILOT_OPENAI_API_KEY first, fallback OPENAI_API_KEY; apply `_clean_api_key()` to both; return cleaned value. OpenAI client uses this cleaned key.
- Optionally strip accidental `VAR=` prefix (pasted line) in key resolution.

### 2. UI fix hint accuracy (frontend)

- **CopilotPanel.tsx**: Fix hint text: “Set COPILOT_OPENAI_API_KEY (preferred) or OPENAI_API_KEY on the backend and restart uvicorn.”
- COPILOT_AUTH_FAILED: same fix hint plus “Key is present but rejected by OpenAI (401).”
- COPILOT_KEY_MISSING: “Key missing” plus the same env hint.
- Keep messages safe: no keys or stack traces in UI.

### 3. Copilot status in system health (backend + frontend)

- **GET /api/ui/system-health** `copilot` object:
  - `enabled`: bool (router mounted and key valid)
  - `key_present`: bool (non-empty after _clean_api_key from either var)
  - `key_source`: `"COPILOT_OPENAI_API_KEY"` | `"OPENAI_API_KEY"` | `"NONE"` (no value)
  - `model`: str (COPILOT_OPENAI_MODEL)
  - `last_error_code`: str | null (module-level, set on 502/503/500)
- Frontend: `UiSystemHealthResponse.copilot` includes `key_source` and `last_error_code`; update tests/build as needed.

### 4. Backend error handling refinement

- On OpenAI auth error: 502 + `COPILOT_AUTH_FAILED`; set `LAST_COPILOT_ERROR_CODE`.
- Key missing: 503 + `COPILOT_KEY_MISSING`; set `LAST_COPILOT_ERROR_CODE`.
- Rate limit/timeouts: 503 + `COPILOT_UPSTREAM_UNAVAILABLE`; set `LAST_COPILOT_ERROR_CODE`.
- Unknown: 500 + `COPILOT_INTERNAL_ERROR`; set `LAST_COPILOT_ERROR_CODE`.

### 5. Tests

- **Backend**: Unit tests for `_clean_api_key()` (trim, quotes, empty/whitespace); auth tests that `_get_copilot_api_key()` accepts quoted env and strips; test that `/api/ui/system-health` includes `copilot.key_present` and `copilot.key_source` (mock env).
- **Frontend**: CopilotPanel.test.tsx asserts fix hint includes “COPILOT_OPENAI_API_KEY (preferred) or OPENAI_API_KEY”.

### 6. Docs + verification

- **docs/releases/R23.4.3_requirements.md**, **docs/releases/R23.4.3_release_notes.md**.
- **out/verification/R23.4.3/notes.md**: gate commands and pasted outputs; manual steps (quoted key in .env, restart uvicorn, system-health copilot, COPILOT_AUTH_FAILED fix hint).
- **chakraops/docs/releases/RELEASE_CHECKLIST.md**: R23.4.3 section; mark items only after evidence is in notes.

## Acceptance criteria

- Key parsing strips quotes and whitespace; no raw env values logged.
- UI fix hint names both env vars and explains 401 case.
- System-health `copilot` has `key_source` and `last_error_code`.
- SDLC gates pass; outputs in `out/verification/R23.4.3/notes.md`.
