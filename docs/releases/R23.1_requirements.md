# R23.1 — Operator Trust Fix Pack: Requirements

## Objectives

- Fix Trade Ticket "contract identity required" when symbol is ELIGIBLE (contract_key consistency).
- Eliminate backend store loader failures (missing reason / why_this_trade).
- Show delta reject transparency (best delta, miss vs band) in Symbol diagnostics.
- Restore always-visible price in Symbol header (Options and Shares tabs).
- Use date picker for Shares "opened date" (no manual YYYY-MM-DD typing).

## Scope

### Part 1 — Contract identity normalization (P0)

- One canonical contract_key format: `{strike_int}-{expiry}-PUT|CALL` (strike as integer, no trailing .0).
- Backend helper `normalize_contract_key(strike, expiry, option_type)`; used when building selected_candidates and candidates_by_symbol.
- Loader normalizes legacy "673.0-..." to "673-..." on load.
- UI uses contract_key as primary identity; no raw FAIL_/WARN_ in UI.

### Part 2 — Store loader compatibility (P0)

- GateEvaluation.reason and CandidateRow.why_this_trade optional (default None).
- from_dict uses dict.get() for optional fields; no exception when loading minimal persisted JSON.
- Regression test: write with to_dict_persist(), load via store get_latest(), key fields present.

### Part 3 — Delta reject diagnostics (P1, request-time only)

- When Stage 2 fails due to delta, compute delta_diagnostics: band_min, band_max, best_delta, miss, direction (TOO_LOW/TOO_HIGH/IN_BAND), best_candidate (strike, expiry, bid, ask, etc.).
- Do NOT persist to decision_latest.json.
- UI: show "Best available delta", "Distance to band", target band, closest contract row (safe text only).

### Part 4 — Symbol header price (P1)

- Price (spot) always visible in Symbol header regardless of Options/Shares tab.
- If price missing, show "—" and optional "Price unavailable".
- quote_as_of shown when available.

### Part 5 — Shares opened date date-picker (P2)

- Use `<input type="date">` for opened_at in Shares tab form.
- Backend continues to accept YYYY-MM-DD.

## Non-goals

- No changes to decision artifact persisted schema (code-only; no prose/diagnostics persisted).
- No new persistence for delta_diagnostics or prose.

## Acceptance criteria

- [ ] Trade Ticket for eligible CSP/CC symbol shows no "contract identity required" when API returns contract_key.
- [ ] Server startup and store reload do not log "missing 'reason'" or "missing 'why_this_trade'".
- [ ] Symbol diagnostics for a delta-rejected symbol (e.g. WMT) show delta_diagnostics with best_delta and miss.
- [ ] Symbol header shows price or "—" on both Options and Shares tabs.
- [ ] Shares "Opened date" uses native date picker (type=date).

## Test plan

- Backend: test_r231_operator_trust.py (normalize_contract_key, consistency selected/candidates, loader compat, from_dict normalizes .0, delta_diagnostics builder).
- Frontend: SymbolDiagnosticsPage score tests (header price when present/absent), Shares opened date type=date; TradeTicketDrawer (identity present when contract_key set).
- Full gate: pytest, frontend test, frontend build.

## UAT checklist

- Open Trade Ticket for eligible CSP symbol → no identity error.
- Server startup → no store load failures in logs.
- WMT (or any delta reject) → best delta + miss vs band visible on Symbol page.
- Price visible on Symbol page header in both Options and Shares tabs.
- Shares "Opened date" uses calendar picker.

## Rollback

- Revert R23.1 commits; no DB migration. If rollback, ensure decision_latest.json remains loadable (optional fields already backward compat).
