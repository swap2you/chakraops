# R30.4 — In-app Readiness Pack Viewer v1 (Journal) (NO GIT)

**NO GIT.** Manual-only. No broker automation. No schedulers.

## Non-negotiables

- Manual-only. No broker automation. No schedulers.
- Do NOT write out/decision_latest.json.
- UI must never display raw FAIL/WARN/PASS or FAIL_/WARN_ substrings.
- Viewer must render only sanitized content. Determinism: viewer ordering stable (checks list and order_stub lines preserve backend order).

## Goal

Allow operator to VIEW the readiness pack inside the app (modal) without downloading. "View readiness pack" when has_readiness_pack=true; modal shows summary, checks (with Fix links), order stub. All text sanitized; no forbidden tokens in DOM.

## Scope

### Backend (minimal)

- No new endpoints. GET /api/ui/journal/entry/{id}/attachment/readiness-pack already returns { manifest, readiness, system_health_subset, notes } with readiness.checks[] and readiness.order_stub.lines[]. Response sanitized (R30.3).
- Optional tests: test_r304_readiness_pack_view_contract.py — attachment returns expected keys; no forbidden tokens; no decision_latest write.

### Frontend

- **API:** uiJournalEntryReadinessPackJsonPath(entryId) (export); useJournalEntryReadinessPack(entryId, enabled) to fetch JSON.
- **JournalPage:** "View readiness pack" button in Pack column when e.has_readiness_pack; data-testid journal-view-readiness-pack. Modal: title "Readiness pack"; Summary (status, label, as_of_utc); Checks table (code, status, label, detail, Fix link if action_href); Order stub (preformatted lines). Loading: "Loading…"; Error: "Readiness pack not available." All dynamic strings via safeForReadinessDisplay (sanitizeForDisplay + redact if forbidden remains).
- **Tests:** View button appears when has_readiness_pack; click opens modal with summary/checks/order stub; no View when has_readiness_pack=false; no forbidden tokens; Fix links render when action_href present and are internal.
