## 1) Symbol Diagnostics → Shares tab: Trade Plan view

**Status: Implemented**

- **Accordion sections (matching Options style):**
  - **Trade Plan** (default open): Card with Spot, Entry zone (low–high), Stop, T1/T2/T3, Invalidation, Hold-time estimate, Why eligible/Why not checklist, Suggested shares (or “Insufficient data” when `sizing.basis === "INSUFFICIENT_DATA"`).
  - **Technicals:** Reused layout — RSI, ATR, Support, Resistance; optional MTF levels blurb.
  - **Risk & Details:** Reused — Score breakdown (when present), Risk flags blurb.
  - **Position:** Your Shares Position (quantity, avg cost, Unrealized P/L when `last_price` available); Update / **Close position** / Delete; “Add Shares Position” when none. “Closed positions (this symbol)” list with Realized P/L when any closed.
- **Trade Plan fields:** Spot, Entry zone (low–high) with optional basis, Stop, T1/T2/T3, Invalidation. All driven by `data.shares_plan` (and fallbacks from `data` where applicable).
- **Hold-time:** Formula line (“Sessions to T1 = ceil(|T1-Spot| / ATR)”); compact line with Spot, T1, ATR, Distance; **plain-English** line: “One session = one trading day. Rough estimate of days to T1 if price moves ~1 ATR per day; not a promise.” **(?) button** opens info drawer (“ATR-based hold time” / “Hold-time estimate”). Shown when `hold_time_estimate.hold_time_atr` and `hold_time_distance_to_t1` are present; otherwise “X sessions” when `hold_time_estimate.sessions` is present.
- **Targets/entry basis:** Entry zone and targets can show a **(?)** that opens the existing info drawer (“Targets basis”).
- **Why eligible / Why not:** Checklist (not prose). Uses `plan.reason_codes` or `plan.eligibility_codes`; each code is rendered via `sharesReasonCodeToLabel()` (e.g. SHARES_ELIGIBLE → “Meets all shares eligibility rules”, NOT_NEAR_SUPPORT → “Not near support”). Label is “Why eligible” when `plan.eligible === true`, “Why not” otherwise. Rendered in a list with ✓/✗.

**Files:** `frontend/src/pages/SymbolDiagnosticsPage.tsx` — `SharesTabContent`, accordions, Trade Plan card, hold-time block, Why checklist, sizing line.

## 2) Shares position lifecycle (Close + history + P/L)

**Status: Implemented**

- **Close position action:** In the Position accordion, when there is an active shares position, a **“Close position”** button is shown. Clicking it opens a modal.
- **Close modal:**
  - **Exit price (required)** — number input.
  - **Exit date (default today)** — date input, default `new Date().toISOString().slice(0, 10)`.
  - **Notes (optional)** — text input.
  - Submit calls `closeSharePosition.mutate({ account_id, exit_price, exit_date, notes })`; on success modal closes and form resets.
- **Backend:** Table `share_positions_closed`; `close_share_position(account_id, symbol, exit_price, exit_date=None, notes=None)` in `chakraops/app/core/accounts/holdings_db.py`. On close: insert into `share_positions_closed` with `realized_pnl` computed (from quantity, avg_cost, exit_price); then delete from active share positions. `list_closed_share_positions(account_id)` for the closed list.
- **API:** `POST /api/ui/shares/positions/{symbol}/close` (body: account_id?, exit_price, exit_date?, notes?); `GET /api/ui/shares/positions/closed?account_id=`.
- **UI after close:** Active position is removed (refetch or cache invalidation). “Closed positions (this symbol)” section shows closed records with **Realized P/L** and closed date. **Unrealized P/L** is shown for the active position when `last_price` (and thus unrealized_pnl) is available.

**Files:**  
- Backend: `chakraops/app/core/accounts/holdings_db.py` (table, `close_share_position`, `list_closed_share_positions`); `chakraops/app/api/ui_routes.py` (close + closed endpoints).  
- Frontend: `SymbolDiagnosticsPage.tsx` (Close button, close modal, closed list, Unrealized/Realized P/L); `frontend/src/api/queries.ts` (`useCloseSharePosition`, `useClosedSharePositions`); `frontend/src/api/types.ts` (`ClosedSharePosition`, etc.).

## 3) Consistency

**Status: Implemented**

- **Shares tab uses API data only:** Shares tab content is driven by `data.shares_plan`, `data.shares_position`, and closed list from `GET /api/ui/shares/positions/closed`. Same data as returned by `/api/ui/symbol-diagnostics` for the symbol (and closed list from the shares API). No local-only state for eligibility/plan.
- **No Shares content on Options tab:** Rendering is `activeTab === "Options" ? <OptionsContent /> : <SharesTabContent />`. Options view does not render `SharesTabContent` or the Trade Plan card; tests assert `shares-trade-plan-card` and entry-zone text (e.g. “98 – 102”) are not present on the Options tab.

**Files:** `SymbolDiagnosticsPage.tsx` (tab conditional, single source of truth from `data`).
