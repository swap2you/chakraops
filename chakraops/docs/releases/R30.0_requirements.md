# R30.0 — Wheel Execution Readiness Pack v1 (NO GIT)

**NO GIT.** Manual-only. No broker automation. No schedulers.

## Non-negotiables

- Manual-only. No broker automation. No schedulers.
- Do not write out/decision_latest.json.
- Decision artifacts are code-only; never persist prose/UI strings in decision artifacts.
- UI must never display raw FAIL/WARN/PASS or FAIL_/WARN_ substrings.
- Determinism: stable ordering, stable outputs for same snapshot inputs.

## Goal

Add an "Execution readiness" pack to Trade Ticket so the operator can safely execute in Robinhood with confidence. Read-only checks from existing state; safe labels only.

## Scope

### Backend: Read-only readiness endpoint

- **GET /api/ui/trade-ticket/readiness**
  - Query: symbol, mode=live|paper (default live), ticket_kind=ENTRY|CLOSE|ROLL|CC (default ENTRY).
  - Response: status (OK|Review), status_label, as_of_utc, checks (array of {code, status, label, detail}), order_stub {title, lines[]}.
  - status=Review if any check is Review; else OK.
  - No FAIL/WARN/PASS or FAIL_/WARN_ in any string; sanitize defensively.
- Build from existing state only: system-health blocks (integrity, reconcile, rebuild, mark refresh, risk notify), trade ticket data (contract, sizing). Do NOT call broker APIs; do NOT persist new state.
- Checks: INTEGRITY, MARK_FRESHNESS, CASH_SECURED_RESERVE, SIZING_CONSTRAINTS, EARNINGS_ADVISORY, ACCOUNT_PRESENT. Deterministic order.
- Tests: test_r300_trade_ticket_readiness.py — safe labels only; deterministic ordering of checks and order_stub.lines; endpoint does not write decision_latest.

### Frontend: TradeTicketPage readiness block

- Card "Execution readiness": overall status + label, list of checks with safe labels, button "Copy order stub" (copies order_stub.lines joined with newline).
- Tests: readiness renders; copy calls clipboard; no forbidden tokens in document.
