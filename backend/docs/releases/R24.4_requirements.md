# R24.4 — Mark Proxy Provenance/Freshness + Roll Rationale (Operator Trust)

## Objective

Add **mark provenance and freshness** (request-time only) and **roll rationale** fields to position lifecycle so operators can trust mark source and age and understand why ROLL is recommended. No persistence to decision artifacts. No raw FAIL_/WARN_ in UI or API.

## Non-negotiables (must not regress)

- Decision JSON artifacts remain code-only. Canonical `out/decision_latest.json` and archived history only.
- Never persist prose/UI strings/panels or raw FAIL_/WARN_ in decision artifacts.
- UI must never display raw FAIL_/WARN_; API must not return them in UI payloads.
- SDLC gates (pytest, frontend test, frontend build) must pass; raw outputs pasted in `out/verification/R24.4/notes.md`.
- Repo hygiene: `out/` whitelist only; no secrets; no scratch.
- Deterministic behavior: universe evaluation vs per-symbol recompute must match under snapshot semantics.
- wheel_state rules (CLEANUP_POLICY, R24.3 retention) remain intact.

## Scope

### Mark proxy provenance and freshness (request-time only)

- **New mark fields (in lifecycle output only, never in decision_latest.json):**
  - `mark_value` (float) — selected mark for pct_max_profit
  - `mark_source` (enum: MID | LAST | BIDASK_MID | BID | ASK | UNKNOWN)
  - `quote_ts` (ISO string when available)
  - `mark_age_sec` (int when quote_ts and as_of time available)
- **Deterministic selection order:** 1) MID (bid and ask present and valid), 2) LAST (present and valid), 3) BIDASK_MID (bid+ask but not "mid" elsewhere), 4) BID, 5) ASK, else UNKNOWN.
- Same inputs → same outputs. None of these fields persisted to decision artifacts.

### Roll rationale (structured, safe)

- When `recommended_action_code == ROLL`:
  - `roll_window_threshold_dte` (e.g. 14)
  - `roll_reason_codes` (safe enum list, e.g. `["DTE_WINDOW"]`)
- Optional roll_candidate only if deterministically available from existing data; otherwise omit.

### API: GET /api/ui/action-needed

- Include mark provenance/freshness and roll rationale in payload when present.
- Payload must contain no FAIL_/WARN_ substrings.

### Slack

- Include mark provenance/freshness and max profit % when present.
- Example: "Mark: 1.23 (MID, 18s old) | Max profit: 52% | Recommend: CLOSE"
- No raw FAIL/WARN.

### Frontend: Dashboard Action Needed

- Show Mark value + source + age (if present).
- Show Max profit %.
- Show Recommend action (safe labels).
- If ROLL: show "Reason: DTE window" (safe mapping from roll_reason_codes).
- Do not render raw codes.

## Non-scope

- No change to decision artifact schema or persistence.
- No new persistence of mark_* or roll_* to decision store.

## Test plan

- **Backend:** Deterministic mark selection (table-driven); mark_age_sec from quote_ts and as_of; action-needed response no FAIL_/WARN_; lifecycle mark_*/roll_* not in decision artifact.
- **Frontend:** Dashboard renders mark/source/age safely; UI textContent does not contain FAIL_|WARN_.
