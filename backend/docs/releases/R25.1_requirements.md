# R25.1 — Offline Proof Harness + Golden Verification (determinism + hygiene without ORATS)

## Scope

Deliver an offline proof harness that runs the same evaluation pipeline used in production with deterministic fixtures (no network, no ORATS), writes decision and snapshot artifacts to a temp output directory, and enforces hygiene (code-only persistence; no raw FAIL_/WARN_ in UI/API or persisted artifacts). Same fixture inputs must produce identical outputs across runs (determinism). Gates pass and evidence recorded in `out/verification/R25.1/notes.md`.

## Non-negotiables

- **Decision artifacts remain code-only** — No prose/UI strings persisted; use reason_code / rank_reason_codes only.
- **No raw FAIL_/WARN_** — Never persist or emit FAIL_/WARN_ substrings in UI or API.
- **Determinism** — Same fixture inputs → identical outputs across runs (normalize or freeze timestamps where needed).
- **Gates** — Backend pytest, frontend tests, frontend build pass; outputs recorded in `out/verification/R25.1/notes.md`.

## Requirements

### 1. Docs

- `chakraops/docs/releases/R25.1_requirements.md` (this file).
- `chakraops/docs/releases/R25.1_release_notes.md`.
- `out/verification/R25.1/notes.md` — scaffold + UAT checklist; paste gate tails and offline proof output.
- `chakraops/docs/releases/RELEASE_CHECKLIST.md` — add R25.1 section.

### 2. Offline fixture provider

- **Module:** `app/core/eval/offline_fixture_provider.py`.
- **Behavior:** Provide deterministic fixtures for:
  - OHLC bars per symbol.
  - Option chain candidates per symbol (with stable `contract_key`).
  - Quotes: spot + option bid/ask/last + `quote_ts`.
  - Account settings needed for sizing.
- **Constraints:** No network calls, no ORATS. All data from fixture JSON or built-in constants.

### 3. Offline proof script

- **Script:** `chakraops/scripts/offline_eval_proof.py`.
- **Flow:** Load fixture → run evaluation pipeline (same core as production) → write `decision_latest.json` and `eval_snapshot.json` into a temp `out/` directory (e.g. under system temp or tests tmpdir; do not pollute repo `out/` by default).
- **Hygiene checks:** No prose fields; no FAIL_/WARN_ substrings anywhere; deterministic contract identity.
- **Output:** Concise report (symbol verdicts + key computed fields).

### 4. Golden tests

- **File:** `tests/test_r251_offline_proof_harness.py`.
- **Assertions:**
  - Run twice → byte-identical or structurally identical outputs for `decision_latest.json` (timestamps normalized or time frozen) and `eval_snapshot.json` semantics.
  - Hygiene: strict code-only persistence; no forbidden substrings.
  - Determinism of mark selection and lifecycle where applicable.

### 5. Gates and verification

- Run: `cd chakraops && python -m pytest -v --tb=short`; `cd frontend && npm run test -- --run`; `cd frontend && npm run build`.
- Paste tails into `out/verification/R25.1/notes.md`.
- UAT: Run `offline_eval_proof.py` and paste output tail; confirm files written only in temp dir (not repo `out/`).

## Out of scope

- ORATS or any live market data.
- Changes to decision artifact schema beyond hygiene (reason_code, no prose, no FAIL_/WARN_).
- UI copy or API response format changes other than ensuring no FAIL_/WARN_ emission.
