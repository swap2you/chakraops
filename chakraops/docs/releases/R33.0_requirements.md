# R33.0 Requirements — Decision Engine, Strategy Profiles, and Risk Correctness

_Program R31–R35, milestone 3 on `release/R31-R35-program`. Risk level 4 (trading-decision logic). Advisory and manual-only._

## Objective

Make ChakraOps recommendations mathematically consistent, profile-driven, portfolio-aware, and safely ranked — with one canonical configuration source and one canonical decision contract. Decisions remain advisory; nothing creates or routes orders, and there is no silent fallback data provider.

## Functional requirements

### Data safety
- The R32 `stale_data_gate` is wired into every path that can produce an actionable recommendation.
- Missing or stale critical data blocks action (status BLOCKED) with explicit reason codes.
- Explicit reasons are preserved for blocked, unavailable, and stay-in-cash outcomes.
- No silent fallback provider.

### Strategy profiles (one canonical source)
- Conservative, Balanced, Aggressive, Custom (Custom derived from Balanced + validated overrides).
- Each profile validates: acceptable regimes, CSP delta range, covered-call delta range, DTE range, minimum return threshold, earnings/event blackout, liquidity requirements, max position allocation, max symbol/sector exposure, cash-buffer requirement, profit-management defaults, actionable-min score, and max recommendations.
- Values live only in `config/strategy_profiles.yaml`, loaded/validated by `app/core/decision_engine/profiles.py`. No conflicting hardcoded profile values elsewhere.

### Strategy eligibility
- CSP, covered-call, and share-buy eligibility + deterministic scoring; explicit stay-in-cash result.
- Gates: event/earnings exclusions, regime gates, liquidity gates, stale/missing-data gates, holdings requirement for covered calls (>= 100 shares), available-cash requirement for CSPs.

### Position sizing and risk
- Portfolio-aware sizing; reserved-cash; existing-position awareness; symbol concentration limits; sector concentration limits where data exists; max allocation by profile; cash-buffer preservation; assignment-stress awareness; deterministic sizing explanations.
- Mandatory invariants: no uncovered covered call; no CSP requiring more reserved cash than available; no negative/impossible quantity; no action from stale/missing critical inputs; no hidden leverage; no automatic order creation or routing.

### Ranking and recommendations
- Deterministic scoring and tie-breaking; reason codes; confidence/data-quality labels; top 5–7 actionable recommendations; separate blocked/watch/cash outcomes; no noisy unbounded recommendation list.

### Canonical decision contract
- One input/output contract covering: symbol, strategy, profile, market regime, data freshness, event risk, eligibility, selected contract, sizing, capital required, expected return metrics, risk flags, score, rank, reason codes, decision status, manual-only safety label.
- Backward compatibility preserved where practical; intentional contract changes documented.

## Non-functional / safety
- Advisory, manual-only. No auto-trading, broker writes, undocumented leverage, silent risk overrides, live deployment, or broad page redesign.
- No secrets in logs or committed evidence.

## Acceptance
- AGENTS.md baseline gates pass (backend pytest, frontend tests, frontend build).
- R33-specific golden vectors, profile matrix, and property/invariant suites pass.
- Evidence stored under `out/verification/R33.0/` (no credentials or account-sensitive data).
