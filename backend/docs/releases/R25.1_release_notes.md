# R25.1 — Offline Proof Harness + Golden Verification

**Date:** 2026-02

## Summary

Offline proof harness and golden verification: run the same evaluation pipeline with deterministic fixtures (no network, no ORATS), write artifacts to a temp output directory, and enforce code-only persistence with no raw FAIL_/WARN_ in artifacts, UI, or API. Same fixture inputs produce identical outputs across runs.

## What changed

- **Docs** — `R25.1_requirements.md`, `R25.1_release_notes.md`, `out/verification/R25.1/notes.md` (scaffold + UAT), RELEASE_CHECKLIST R25.1 section.
- **Offline fixture provider** — `app/core/eval/offline_fixture_provider.py`: deterministic fixtures for OHLC per symbol, option chain candidates (stable `contract_key`), quotes (spot + option bid/ask/last + quote_ts), account settings for sizing. No network, no ORATS.
- **Offline proof script** — `chakraops/scripts/offline_eval_proof.py`: load fixture → run evaluation pipeline → write `decision_latest.json` and `eval_snapshot.json` to temp out/ → hygiene checks (no prose, no FAIL_/WARN_, deterministic contract identity) → concise per-symbol report. Default output to temp dir to avoid polluting repo `out/`.
- **Golden tests** — `tests/test_r251_offline_proof_harness.py`: run-twice determinism (byte- or structure-identical outputs with timestamps normalized), hygiene assertions, determinism of mark selection/lifecycle.
- **Verification** — Gate outputs and UAT in `out/verification/R25.1/notes.md`.

## How to run offline proof

**From repo root:**

```bash
python chakraops/scripts/offline_eval_proof.py --fixture chakraops/tests/fixtures/r25_1_offline_fixture.json
```

**From chakraops:**

```bash
python scripts/offline_eval_proof.py --fixture tests/fixtures/r25_1_offline_fixture.json
```

Artifacts are written to a temp directory by default (see script `--output-dir`). To use repo `out/` explicitly: `--output-dir out`.

## How to populate verification notes

Create `out/verification/R25.1/notes.md` locally and paste the content generated by:

```bash
python chakraops/scripts/print_r251_verification_notes.py
```

Run the gate commands and offline proof script, capture their tails into files, then pass them in for a filled template:

```bash
python chakraops/scripts/print_r251_verification_notes.py --pytest-tail-file pytest_tail.txt --frontend-test-tail-file frontend_test_tail.txt --build-tail-file build_tail.txt --offline-proof-tail-file offline_proof.txt
```

Paste the script output into `out/verification/R25.1/notes.md`. The script does not write to `out/` (avoids permission issues).

## Non-negotiables

- Decision artifacts code-only; no prose/UI strings persisted.
- No raw FAIL_/WARN_ persisted or emitted in UI/API.
- Determinism: same fixture → identical outputs.
- Gates pass; evidence in `out/verification/R25.1/notes.md`.
