# R25.6 — Phase 6 Universe Expansion Process + Quarterly Review (Requirements)

## Scope

Universe governance (add/remove criteria, cadence), in-app Universe Admin workflow with propose/apply and SQLite audit, deterministic universe ordering, and Universe Health report. Single source of truth remains existing base (config/universe.csv) + overlay (out/universe_overrides.json); evaluation unchanged.

## Non-negotiables

- **Decision artifacts code-only** — No prose/UI strings or FAIL_/WARN_ in decision_latest.json.
- **UI** — Never show raw FAIL/WARN; use safe labels only.
- **Determinism** — Universe ordering stable; no noisy diffs.
- **SQLite under data/** — Audit store in data/ (e.g. data/universe_admin.db); not under out/.
- **Gates** — Backend pytest, frontend tests, frontend build pass; evidence in out/verification/R25.6/notes.md.

## 1) Universe governance (docs + rules)

- **Add criteria (advisory):** Liquidity, price floor, options liquidity, spreads, assignment risk tolerance.
- **Remove criteria (advisory):** Illiquidity, extreme volatility, repeated failures, data unavailable.
- **Cadence:** Monthly quick check (5 min); quarterly full review (30–60 min) with checklist.
- **Sector balance:** Advisory only, not a hard blocker.

## 2) Universe change workflow (in-app)

- **Universe Admin page:** Current universe list (search, sort); Propose Add/Remove (symbol + reason_code + optional notes); Apply changes (writes to overlay) only after Confirm.
- **SQLite audit table (universe_change_log):** id, ts, actor, action (PROPOSE_ADD | PROPOSE_REMOVE | APPLY_ADD | APPLY_REMOVE), symbol, reason_code, notes, status (OPEN | APPLIED | CANCELLED).

## 3) Universe source of truth

- Keep existing: base from config/universe.csv, effective = (base union overlay.added) minus overlay.removed.
- Deterministic update: validate symbol, dedupe, sort A-Z, write overlay once. Evaluation uses get_universe_symbols().

## 4) Universe Health

- Page: total symbols, recently added/removed (last 30 days), warnings count (safe labels), earnings upcoming if available.
- API: GET /api/ui/universe/health.

## 5) APIs

- GET /api/ui/universe/admin — current list + recent history.
- POST /api/ui/universe/propose-add, POST /api/ui/universe/propose-remove, POST /api/ui/universe/apply.
- GET /api/ui/universe/health.

## 6) Tests

- Backend: deterministic write; audit trail; apply updates overlay; no FAIL_/WARN_ in responses.
- Frontend: Admin and Health pages render; no FAIL/WARN in document.

## Verification

- Gate outputs and UAT in out/verification/R25.6/notes.md.
