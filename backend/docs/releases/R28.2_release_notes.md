# Release R28.2 — Safe labels in UI-facing runtime state files

**Date:** 2026-03  
**Branch:** release/R28.2  
**Goal:** Persist only safe status/label in `out/mark_refresh_state.json` and `out/portfolio_risk_notify_state.json`; no raw FAIL/WARN/PASS in those files or in API/UI.

---

## What changed

### Backend

- **Shared helper** `app.core.portfolio.runtime_state_safe_labels`:  
  - `normalize_runtime_status(raw)` → (safe_status, safe_label): PASS→(OK, OK), FAIL→(Blocked, Limit breach), WARN→(Degraded, Advisory).  
  - `normalize_mark_refresh_result(raw)`: PASS→(OK, OK), FAIL→(Blocked, No update), WARN→(Degraded, Partial update).

- **mark_refresh_state.py**  
  - `write_mark_refresh_state` persists `status`, `status_label` (and existing counts/samples). No `last_result` = PASS/FAIL/WARN.  
  - `load_mark_refresh_state` returns safe fields; backward compat: if file has old `last_result`, normalizes and exposes `status` / `status_label` and `last_result` = safe status.

- **risk_notify_state.py**  
  - `_save_state` persists only `status` and `status_label` (no `last_status` = FAIL/WARN).  
  - `get_portfolio_risk_notifier_display` reads `status` / `status_label`; backward compat for old files with `last_status`.  
  - `should_emit_portfolio_risk_notification` still receives raw FAIL/WARN from caller; compares normalized safe status for transitions; persists only safe values.

- **System-health**  
  - `_get_mark_refresh_health` returns `status`, `status_label` (no raw `last_result`).  
  - `portfolio_risk_notifier` already returned safe status/label; unchanged.

### Frontend

- **Types:** `UiSystemHealthMarkRefresh` has `status`, `status_label`; `last_result` deprecated (optional compat).  
- **SystemDiagnosticsPage:** Mark Refresh card shows `status` (and `status_label` when present); no raw PASS/FAIL/WARN.

### Tests

- **Backend:** `test_r282_runtime_state_safe_labels.py` — writer output has no FAIL/WARN/PASS; no write to decision_latest; backward compat; normalize helper.  
- **Frontend:** System Diagnostics tests use safe mark_refresh/portfolio_risk payloads; R28.2 test asserts no FAIL/WARN/PASS in document.

## Backward compatibility

- Old `mark_refresh_state.json` with `last_result`: loader normalizes and returns safe `status`/`status_label` and `last_result` = safe status.  
- Old `portfolio_risk_notify_state.json` with `last_status`: display path normalizes for UI; save path writes only safe fields on next write.
