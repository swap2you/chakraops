# R26.7 — Restore drill + smoke test (prove backups are usable)

## Scope

Ops-only: script that restores latest out/data backups into a temp dir, runs the backend with env overrides, and hits health + system-health + reports endpoints to prove backups are usable. Minimal backend support for OUT_DIR and DATA_DIR env overrides.

## Non-negotiables

- No secrets committed.
- Do not write into decision artifacts besides normal behavior.
- No FAIL_/WARN_ raw codes in UI; ops-only.
- Gates + evidence in out/verification/R26.7/notes.md + UAT.

## 1) Script: scripts/restore_drill.sh

- Find latest backups in ./backups (out_*.tar.gz, data_*.tar.gz).
- Create temp dir (mktemp -d); extract archives so temp has ./out and ./data.
- Export OUT_DIR=<temp>/out, DATA_DIR=<temp>/data.
- Start backend (uvicorn) on port 8010 in background.
- Wait for /api/healthz OK (retry loop).
- Call: GET /api/healthz, GET /api/ui/system-health, GET /api/ui/reports/monthly?month=, POST /api/ui/reports/monthly/close?month=.
- Print "DRILL OK" and temp paths; shut down backend and clean up unless --keep.

## 2) Backend: OUT_DIR and DATA_DIR overrides

- OUT_DIR: if set at process start, decision store (evaluation_store_v2) uses it.
- DATA_DIR: if set, journal, checklist, monthly_close, universe_admin use it for DB/reports paths.
- Minimal and deterministic; tests can still override via existing set_*_path.
