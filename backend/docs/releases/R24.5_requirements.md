# R24.5 — Earnings Advisory (Hero Pill + Risk Flags) Using ORATS

## Objective

Add **earnings advisory** (hero pill + risk flags) using ORATS cores (and optional hist/earnings). **No hard blocker** for options or shares — advisory only. Operators see next earnings date, days, implied move %; eligibility is not blocked/failed due to earnings.

## Non-negotiables (must not regress)

- Decision JSON artifacts remain code-only; do not persist UI strings/prose.
- Never persist raw FAIL_/WARN_ anywhere. UI must never display raw FAIL_/WARN_ codes; API must not return them.
- Deterministic behavior: universe run snapshot vs per-symbol recompute must match under snapshot semantics.
- Gates must pass; raw outputs pasted into `out/verification/R24.5/notes.md`.

## Scope

### Backend: ORATS earnings fetch + request-time fields

- **ORATS fetch:** `/datav2/cores` with fields including `ticker`, `nextErn`, `daysToNextErn`, `impliedEarningsMove` (and `ieeEarnEffect` if available). Optional: `/datav2/hist/earnings?ticker=...` to derive `anncTod` (AMC/BMO) for nextErn date.
- **Request-time earnings fields** (for symbol diagnostics payload; never in decision artifact):
  - `earnings_next_date` (YYYY-MM-DD or ISO)
  - `earnings_days` (int, calendar days from "as_of" in America/New_York)
  - `earnings_annc_tod` (AMC/BMO/Unknown) if derivable
  - `implied_earnings_move_pct` (float) if available
  - `earnings_data_status` (OK / Unavailable / Stale) — **safe values only**
  - `earnings_as_of` (ISO timestamp)
- **Snapshot semantics:** During universe evaluation, store earnings data in the snapshot store so per-symbol recompute (without force refresh) uses the same values. Do not write any earnings fields into decision artifacts.
- **API hygiene:** No substring FAIL_ or WARN_ in JSON responses. Replace "Not evaluated" with "Unavailable" when earnings status not OK.

### Frontend: Hero pill + Risk Flags

- **Hero pill:** Orange pill when `earnings_data_status == OK` and `earnings_next_date` exists: "Earnings: Today" / "Earnings: 1d" / "Earnings: Feb 25"; append "(AMC)" or "(BMO)" if present.
- **Risk Flags:** Replace "Not evaluated" with "Unavailable" when status not OK. Show: next date, days, implied move %. Add small "Advisory only" note near earnings info (UI only).

## Non-scope

- Earnings must **not** block or fail eligibility (advisory only).

## UAT checklist

- [ ] NVDA shows earnings date + days in ChakraOps (compare against ORATS response).
- [ ] No eligibility is blocked/failed due to earnings (advisory only).
- [ ] `grep -E "FAIL_|WARN_" out/decision_latest.json` returns no matches.
