# R30.2 — Readiness Pack Export v1 (NO GIT)

**NO GIT.** Manual-only. No broker automation. No schedulers.

## Non-negotiables

- Manual-only. No broker automation. No schedulers.
- Do NOT write out/decision_latest.json.
- Decision artifacts remain code-only; never persist prose/UI strings in decision artifacts.
- UI must never display raw FAIL/WARN/PASS or FAIL_/WARN_ substrings.
- Export must contain no forbidden tokens and no secrets. Deterministic ordering.

## Goal

Add a manual "Download readiness pack" action on Trade Ticket that exports a small deterministic, sanitized bundle for the current symbol/mode/ticket_kind: readiness response, subset of system-health blocks relevant to readiness, and ticket context. No persistence. No notifications. No decision writes.

## Scope

### Backend: GET /api/ui/trade-ticket/readiness-pack

- **Query:** symbol (required), mode=live|paper (default live), ticket_kind=ENTRY|CLOSE|ROLL|CC (default ENTRY), include_paper=true|false (default true).
- **Response:** Content-Type application/zip; Content-Disposition attachment; filename="readiness_pack_<symbol>_<utc_ts>.zip".
- **ZIP contents (all JSON, sanitized, deterministic):**
  - **manifest.json:** generated_at_utc, symbol, mode, ticket_kind, include_paper, included_files list, counts.
  - **readiness.json:** output of existing readiness builder (same as GET /api/ui/trade-ticket/readiness).
  - **system_health_subset.json:** positions_unified_reconcile, positions_unified_rebuild, positions_unified_integrity_check, mark_refresh, portfolio_risk_notifier; all strings sanitized.
  - **notes.json:** overall status + label, list of check codes + statuses, order_stub lines; no forbidden tokens.
- Use existing **sanitize_json_for_export** (recursive string sanitize, sorted dict keys). No secrets. Deterministic.

### Backend tests: test_r302_trade_ticket_readiness_pack.py

- test_pack_zip_contains_expected_files (manifest, readiness, system_health_subset, notes).
- test_pack_contains_no_forbidden_tokens (open zip, read JSON, assert no \b(FAIL|WARN|PASS)\b and no FAIL_/WARN_).
- test_pack_deterministic_for_fixed_fixture (same inputs → identical parsed JSON contents).
- test_pack_does_not_write_decision_latest.

### Frontend

- **API:** readinessPackPath(symbol, mode, ticketKind, includePaper); downloadReadinessPack(...) using apiGetBlob, triggers download with timestamped filename.
- **TradeTicketPage:** Button "Download readiness pack" in Execution readiness card; uses current symbol, mode (paperMode), ticketKind, include_paper=true. No forbidden tokens in UI copy.
- **Tests:** Mock downloadReadinessPack; assert button present and clicking calls it with correct args; assert no forbidden tokens in document.
