# R24.6 — UI Audit + Safe Labels + Account Reset Clarity

## Requirements

1. **Safe labels (no FAIL/WARN in UI)**
   - Gate/status badge text: PASS → "Passed", FAIL → "Blocked", WARN → "Degraded".
   - Single helper used globally; no literal "FAIL" or "WARN" (word-boundary) in any rendered UI.
   - System/Diagnostics tables and Gate Summary use the same mapping.

2. **Account reset clarity**
   - When holdings or account exist but positions/tracked positions are empty, show a short "Data reset likely" info note with safe guidance: "Positions are empty. If you deleted state files, re-add positions via Trade Ticket or import."
   - In-app pointer to cleanup/docs (no raw paths in persisted artifacts).

3. **Earnings UI guardrails**
   - Hero pill only when earnings status OK and next date valid (already in R24.5.1).
   - Risk Flags show "Unavailable" when status not OK; no 0000-00-00.
   - Details drawer: optional debug line "earnings status + as_of" (request-time only).

4. **Tests**
   - FE: Regression test that no UI contains word-boundary FAIL or WARN.
   - Backend: Existing no FAIL_/WARN_ payload tests unchanged.

5. **Non-negotiables**
   - No prose in decision artifacts; no FAIL_/WARN_ persisted; determinism unchanged; gates + evidence in out/verification/R24.6/notes.md.
