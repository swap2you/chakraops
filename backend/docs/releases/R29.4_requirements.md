# R29.4 — Integrity Check details/history + System Diagnostics parity

**NO GIT.** Manual-only. No new sources-of-truth; expose what already exists.

## Goal

Make the Integrity workflow usable without bouncing between pages: show last integrity check details (summary + sample items), optional short history, and surface the same block in System Diagnostics. Manual-only, deterministic, safe-labeled.

## Non-negotiables

- NO git operations. NO schedulers/background automation. Manual-only via UI button + confirm.
- NO writes to out/decision_latest.json from any integrity/diagnostics endpoint.
- NO raw tokens in API/UI/state: forbid FAIL, WARN, PASS and FAIL_/WARN_. Sanitize before return/render.
- Deterministic ordering for any lists (history newest first; sample items by symbol, instrument_type, id).

## Scope

### A) Backend

- **State file** (runtime-only): `out/positions_unified_integrity_check_state.json`. Persist: status, status_label, started_at_utc, finished_at_utc, missing_count, extra_count, mismatched_count, sample_items (capped). No verbose messages; sanitize any text.
- **GET /api/ui/positions/unified/integrity-check**: Read-only. Response: `{ status, status_label, last: {...}, history: [...] }` (history capped e.g. 10). Deterministic: history newest first; sample items sorted.
- **System-health**: Include integrity-check block with last status/label, timestamps, counts, last_sample_items. Read-only; no notification triggers.

### B) Frontend

- **PositionsPage**: Show last integrity check status + timestamp + counts; "View details" toggle for sample items (kind, symbol, instrument_type, id, fields_diff); "View full diff in Diagnostics" link; keep Run integrity check button.
- **SystemDiagnosticsPage**: Card "Unified Positions Integrity Check" with same summary + details toggle. Prefer system-health block.
- **Sanitization**: Single UI helper (sanitizeForDisplay) for all integrity strings and fields_diff; no PASS/FAIL/WARN or FAIL_/WARN_.

### C) Tests

- Backend: test_r294_* — safe labels only; no decision write; deterministic ordering; state file safe.
- Frontend: PositionsPage last check summary + expand details; SystemDiagnosticsPage Integrity Check card + details; no forbidden tokens in document.

### D) Docs + verification

- R29.4_requirements.md, R29.4_release_notes.md; R29.4 section in RELEASE_CHECKLIST.md.
- out/verification/R29.4/notes.md: gate commands, tails, UAT, grep proof.
