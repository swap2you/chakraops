# R24.9 — Internet-safe deployment baseline (HTTPS + basic auth + same-origin routing)

## Scope

Add production deployment profile: Caddy reverse proxy, same-origin API routing, HTTPS (Let's Encrypt when domain set), and basic auth. No secrets committed; Docker images do not bake secrets. Decision artifact semantics and UI safe labels unchanged.

## Requirements

1. **Same-origin API routing**
   - Production builds: frontend uses relative `/api` (no hard-coded backend URL). Set `VITE_API_BASE_URL` to empty (or omit) for prod so browser requests go to same origin; Caddy proxies `/api/*` to backend.
   - Dev profile: keep current behavior (frontend can use `http://localhost:8000` for direct backend access; ports 8000 and 3000 exposed).

2. **Compose profiles**
   - **dev** (default): backend ports 8000, frontend 3000; `VITE_API_BASE_URL=http://localhost:8000` for build. For local debugging.
   - **prod**: Caddy listens 80/443; backend and frontend not published (internal only). Caddy proxies `/` → frontend, `/api/*` → backend.

3. **Caddy reverse proxy**
   - Service in docker-compose (prod profile).
   - Proxies: `/` → frontend container; `/api/*` → backend container.
   - Caddyfile: TLS via Let's Encrypt when DOMAIN is set; basic auth on all routes. Credentials from environment (BASIC_AUTH_USER, BASIC_AUTH_HASH); hash generated with `caddy hash-password`; stored in server .env only.
   - Optional: light rate limit (document if not feasible in this release).

4. **Security hygiene**
   - CORS: when same-origin, backend can restrict origins (e.g. UI_CORS_ORIGINS for prod). No debug endpoints exposed without auth (all behind proxy basic auth).
   - Slack/ORATS tokens only in runtime env_file; never in images or repo.

5. **Documentation**
   - README: "Production (VM) Quickstart" — copy .env.example to .env on server; set DOMAIN, BASIC_AUTH_USER, BASIC_AUTH_HASH, ORATS token; `docker compose --profile prod up -d --build`. How to generate Caddy password hash. Ports: only 80/443 open to internet in prod.

6. **Gates and verification**
   - Existing gates (pytest, frontend test, frontend build) pass; outputs in out/verification/R24.9/notes.md.
   - UAT: dev compose works; prod profile runs; frontend loads; /api/ui/system-health works through proxy with basic auth; backend port 8000 not exposed in prod.

## Non-negotiables

- No secrets committed (.env, passwords, keys). Docker images do not bake secrets.
- UI does not display raw FAIL/WARN (no regression).
- Decision artifact semantics unchanged.
- Gates pass; outputs pasted in out/verification/R24.9/notes.md.
