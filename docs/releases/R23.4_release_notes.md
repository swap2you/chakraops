# Release R23.4 — Ticker Copilot v1 (read-only, evidence-grounded Q&A)

**Date:** 2026-02  
**Goal:** Add a read-only Copilot panel on the Symbol page so users can ask natural questions about the current ticker (e.g. "Why not eligible?", "What delta missed the band?", "Is data fresh?") and get answers grounded in ChakraOps API data and allowlisted docs.

---

## Scope

### Backend

- **POST /api/ui/copilot/ask** — Request: symbol, question (required), conversation_id?, mode (symbol | general). Response: answer_markdown, citations, followups, used_tools, snapshot_used, request_id.
- **OpenAI** — Server-side only. **R23.4.1:** API key from **COPILOT_OPENAI_API_KEY** (fallback: **OPENAI_API_KEY** if unset). Model from COPILOT_OPENAI_MODEL (default gpt-4o). Chat Completions with tool/function calling.
- **Tools (read-only):** get_symbol_diagnostics, get_decision_latest, get_universe_row, get_positions_tracked, get_account_default, get_account_holdings, get_share_position, get_delta_override, get_system_health, search_docs.
- **Safety:** Output post-processor replaces any response containing FAIL_*, WARN_*, api key, token, or internal path with a safe "not enough data" message.
- **Docs:** search_docs searches only allowlisted markdown files (Phase 23 releases, RELEASE_CHECKLIST, phase_22 doc).

### Frontend

- **Copilot panel** on Symbol page (right column when symbol loaded): text input, send, message list, loading/error states.
- **Default chips:** "Why is this symbol not eligible?", "What delta missed the band?", "Support/resistance?", "Position/holdings exposure?", "Is data fresh?".
- **Safe markdown** rendering (escape HTML; **bold** supported); Copy answer button.

### Guards

- No writes: copilot cannot place orders, change overrides, or modify holdings/positions/accounts.
- No persistence: no copilot output in out/decision_latest.json or any decision_*.json.
- No raw codes in UI: existing safe-label mappings; copilot output sanitized.

## R23.4.1 — Copilot auth + error handling (patch)

- **Key config:** Use **COPILOT_OPENAI_API_KEY** in backend env (or **OPENAI_API_KEY** as fallback). No other key sources. Startup log: `[COPILOT] enabled=<bool> key_present=<bool> model=<...>` (key never printed).
- **Error responses:** On failure the API returns JSON `{ "error_code", "message" }` with an appropriate HTTP status. No raw stack traces or secrets to the client; server logs redact `sk-` in error messages.

| HTTP status | error_code | Meaning |
|-------------|------------|--------|
| 503 | COPILOT_KEY_MISSING | No API key set. Set COPILOT_OPENAI_API_KEY and restart. |
| 502 | COPILOT_AUTH_FAILED | OpenAI rejected the key (e.g. invalid/expired). Verify key and restart. |
| 503 | COPILOT_UPSTREAM_UNAVAILABLE | Rate limit or upstream timeout. Try again later. |
| 500 | COPILOT_INTERNAL_ERROR | Unexpected server error. Check server logs. |

- **UI:** When the API returns an `error_code`, the Copilot panel shows a "Copilot unavailable" banner with the message and a "How to fix" line (e.g. set key and restart uvicorn).

## How to test

1. Set **COPILOT_OPENAI_API_KEY** (or OPENAI_API_KEY) and optionally COPILOT_OPENAI_MODEL on the server.
2. Open Symbol page, enter a symbol, click Lookup.
3. In Copilot panel, click a chip or type a question and send.
4. Confirm answer is grounded (citations / used_tools) and no raw FAIL_/WARN_ in text.
5. Ask "what's the ORATS token?" — response should be the safe replacement message, not the secret.
6. **R23.4.1:** With key unset, Copilot shows "Copilot unavailable" and fix text; after setting key and restarting, success response returns.
