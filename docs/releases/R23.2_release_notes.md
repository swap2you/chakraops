# Release R23.2 — Delta Transparency + Near-Miss + Optional Delta Override + Gate Code Persistence

**Date:** 2026-02  
**Goal:** Persist gates as code-only (gate_code); delta reject visibility (best_delta, miss, BELOW_BAND/ABOVE_BAND); near-miss code DELTA_NEAR_MISS; optional per-symbol delta override (advanced) with API and UI.

---

## Scope

### Part 1 — Gate code persistence

- **Persist:** gates_by_symbol[*] output only `gate_code` + `status` (e.g. STOCK_QUALITY_STAGE1, OPTIONS_LIQUIDITY_STAGE2). No `name`, no `reason`.
- **Loader:** Backward compat — if JSON has `name`, map to gate_code via gate_name_to_code(); if has `gate_code`, use it and set name from gate_code_to_label() for in-memory/API.
- **API:** Gate list in symbol-diagnostics returns safe label (name) from gate_code at request time.

### Part 2 — Delta transparency

- **delta_diagnostics** (request-time only): band_min, band_max, best_delta, miss, direction (BELOW_BAND | ABOVE_BAND | IN_BAND), best_candidate (strike, expiry, bid, ask, spread).
- **UI:** "Delta band (rejected)" card with best delta, distance to band, direction as safe text ("below band" / "above band"), closest contract row.

### Part 3 — Near-miss and override

- **Config:** DELTA_NEAR_MISS_EPS = 0.02, DELTA_OVERRIDE_MAX_WIDEN = 0.05 (trade_rules).
- **Near-miss:** When primary_reason_codes contains REJECTED_DUE_TO_DELTA and miss ≤ EPS, add DELTA_NEAR_MISS (code-only). Verdict unchanged.
- **Override file:** chakraops/data/delta_overrides.json (NOT under out/). Format: `{ "SYMBOL": { "delta_lo", "delta_hi", "updated_at_utc" } }`. Enforced within max_widen of canonical band.
- **API:** GET /api/ui/delta-overrides, POST /api/ui/delta-overrides/{symbol} (body: delta_lo, delta_hi), DELETE /api/ui/delta-overrides/{symbol}.
- **Evaluation:** Stage-2 uses get_effective_delta_band(symbol, canonical_lo, canonical_hi, max_widen) when calling run_csp_stage2_v2.
- **UI:** Symbol page Delta card shows "Override active" badge when override present; "Adjust delta band (Advanced)" section only when Show Advanced; Save/Reset override.

### Part 4 — Tests and verification

- **Backend:** test_r232_delta_transparency.py — gate_name_to_code/gate_code_to_label, persisted gates gate_code only, delta_diagnostics BELOW_BAND/ABOVE_BAND, override boundaries, overrides not in decision JSON.
- **Verification:** out/verification/R23.2/notes.md with gate outputs, grep proofs (no "name" in gates, no FAIL_/WARN_ in decision JSON), UAT checklist.

---

## API changes

| Method | Path | Description |
|--------|------|-------------|
| GET | /api/ui/delta-overrides | List per-symbol delta overrides. |
| POST | /api/ui/delta-overrides/{symbol} | Set override (body: delta_lo, delta_hi). Validated against max_widen. |
| DELETE | /api/ui/delta-overrides/{symbol} | Remove override. |

- **GET /api/ui/symbol-diagnostics:** Response may include `delta_override` for the symbol when an override exists (for UI badge and form).

---

## Data / persistence

- **Decision JSON:** Gates persisted as `gate_code` + `status` only. No `delta_override` or delta_overrides in artifact.
- **New file (not in out/):** chakraops/data/delta_overrides.json. Whitelist not required; documented in checklist.
