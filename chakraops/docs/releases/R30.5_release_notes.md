# Release R30.5 — Journal Readiness Pack Ops: filter + bulk export (JSONL)

**Date:** 2026-02  
**NO GIT.** Manual-only.

**Goal:** Journal page can filter by "Has readiness pack" and download a bulk JSONL export of readiness packs for the current filter/date range. Deterministic, sanitized, no decision write.

---

## User-visible changes

- **Journal page — Filters:** New **"Has readiness pack"** checkbox (default On). When On, only entries that have an attached readiness pack are shown; when Off, all entries in the date range are shown.
- **Journal page — Actions:** New **"Download readiness packs (JSONL)"** button. Downloads a single file `readiness_packs_<utc_ts>.jsonl` containing one JSON object per line: `{ journal_entry: { id, symbol, created_at_utc, mode, strategy }, readiness_pack: { manifest, readiness, system_health_subset, notes } }`. Uses current month (date range), has_pack filter, and limit 200.

## API / backend

- **GET /api/ui/journal/readiness-packs/export** — Query: has_pack (default true), start_utc (optional), end_utc (optional), limit (default 200, max 1000). Returns JSONL with deterministic order (created_ts ASC, id ASC). Each line is sanitized via sanitize_json_for_export. No state writes; no decision_latest write.

- Frontend: JournalPage — filter toggle; download button and params; no forbidden tokens. Evidence: out/verification/R30.5/notes.md.
