# R23.3 — Shares Recommendation Spine (Eligibility + Plan + Sizing + Universe Badge)

## Objectives

- Shares eligibility: code-only rules (stock quality pass, regime preferred, near support, RSI in range, data OK); request-time only; never persisted.
- Shares plan: request-time shares_plan in symbol-diagnostics with entry_zone (basis), stop (basis), targets (basis), hold_time (method), sizing (suggested_shares, max_loss, basis ACCOUNT_RISK or INSUFFICIENT_DATA).
- Sizing: Risk budget = account value × SHARES_RISK_PCT_DEFAULT; suggested_shares = floor(risk_budget / stop_dist); cap by available cash.
- Universe: Shares column (ELIGIBLE / NOT_ELIGIBLE / N/A), Shares eligible filter, sort by Shares eligibility.

## Scope

### Part A — Shares eligibility (backend, request-time; code-only)

- SHARES_ELIGIBLE when: stock_quality pass, regime UP (or NEUTRAL if config), near support (distance_pct ≤ SHARES_NEAR_SUPPORT_PCT), RSI in range (or bypass if missing), data freshness OK.
- /api/ui/symbol-diagnostics includes shares_plan: eligible, reason_codes (code-only), spot, entry_zone (low, high, basis), stop (price, basis), targets (t1, t2, basis), hold_time (sessions_to_t1, method), sizing, as_of_inputs.
- Config: SHARES_NEAR_SUPPORT_PCT, SHARES_RISK_PCT_DEFAULT, SHARES_ALLOW_REGIME_NEUTRAL, SHARES_ENTRY_ZONE_ATR_MULT, SHARES_STOP_ATR_MULT.

### Part B — Sizing (backend, request-time)

- Risk budget = account_value × SHARES_RISK_PCT_DEFAULT; suggested_shares = floor(risk_budget / stop_dist); cap by available_cash.
- If account data missing: sizing.basis = INSUFFICIENT_DATA; plan still returned.

### Part C — UI Shares tab (Plan view)

- Eligibility badge (Eligible / Not eligible); Why list from reason_codes (safe labels).
- Plan card: spot, entry zone, stop, targets, hold-time, sizing (or Insufficient data).
- Tooltips for entry zone basis, hold-time, sizing method.
- Your Shares Position and Add/Update unchanged.

### Part D — Universe

- Shares column: ELIGIBLE / NOT_ELIGIBLE / N/A (safe display).
- Filter chip Shares eligible; sort option Sort by Shares eligibility (eligible first).

### Part E — Tests

- Backend: test_r233_shares_plan.py (eligibility, plan monotonicity, sizing with/without account, no shares_plan in artifact).
- Frontend: SymbolDiagnosticsPage Shares tab; UniversePage Shares column and filter.

### Part F — Docs and verification

- R23.3_requirements.md, R23.3_release_notes.md, RELEASE_CHECKLIST.md, out/verification/R23.3/notes.md with gate outputs and UAT.

## Non-goals

- Decision JSON remains code-only; shares_plan is never persisted.
- No broker/order placement; advisory only.

## Acceptance criteria

- Persisted decision JSON has no shares_plan, no prose, no FAIL_/WARN_.
- Symbol-diagnostics returns shares_plan with reason_codes (code-only); UI shows safe labels.
- Sizing computed when account data present; INSUFFICIENT_DATA when not.
- Universe shows Shares column and Shares eligible filter; sort by shares eligibility.

## UAT checklist

- Find a shares-eligible symbol (or relax thresholds); verify Shares tab shows plan and sizing.
- Add shares position; verify portfolio shows it.
- Universe: Shares eligible badge and filter work.
- Grep: grep -E "shares_plan|Entry zone|Stop|Target|Not eligible|FAIL_|WARN_" out/decision_latest.json — no matches.

## Rollback

- Revert R23.3 commits. No migration; shares_plan is request-time only.
