# R28.3 — Notifications safe labels (no FAIL/WARN/PASS in UI-facing data)

**Branch:** release/R28.3 (operator creates)  
**Manual-only.** No broker automation.

## Goal

Harden notifications so UI-facing notification data and UI rendering cannot leak raw FAIL/WARN/PASS tokens. Normalize notification severity/status to safe labels consistently: persist and return only safe fields; backward-compatible read of legacy entries; UI renders only safe labels.

## Non-goals

- No change to decision artifact pipeline or schema.
- No rename of notification types or break of dedupe/state machine.

## Non-negotiables

- Decision JSON artifacts remain code-only; no prose/UI strings; no raw FAIL_/WARN_ in decision artifacts.
- UI must never display raw FAIL/WARN/PASS (and for this release: forbid PASS in UI textContent).
- Repo hygiene: out/ only whitelisted artifacts; no secrets.
- Determinism preserved (ordering/dedupe semantics unchanged).

## Scope

### A) Backend — safe-label normalization for notifications

- **Helper module** `app/core/notifications/notification_safe_labels.py`:
  - `normalize_notification_severity(raw)` → (safe_severity, safe_label). Map INFO/PASS→Low, WARN→Medium/Advisory, CRITICAL/ERROR/FAIL→High/Review. No FAIL/WARN/PASS in output.
  - `normalize_notification_status(raw)` → (safe_status, safe_label). Conservative unknown→Review.
  - `sanitize_message_for_api(msg)` — replace \\b(FAIL|WARN|PASS)\\b in message for API response.

- **Write path** (append to notifications.jsonl):
  - Newly written notifications persist only safe fields: `severity`, `severity_label`. Do not persist raw WARN/FAIL/PASS.

- **Read path / API**:
  - When loading notifications, normalize legacy raw severity into safe fields before returning. Sanitize message for API. Never return raw FAIL/WARN/PASS in payload. Ordering/dedupe unchanged.

### B) Frontend

- Types: add `severity_label` to notification payload.
- Notifications page (and any component rendering notification severity/status): use safe fields only; use gateStatusToLabel so raw values never displayed.
- sanitizeMessageForDisplay: extend to replace \\bPASS\\b so UI never shows PASS.

### C) Tests

- Backend: test_r283_notifications_safe_labels.py — persisted line has no FAIL/WARN/PASS; legacy entry normalized on load; no decision_latest write; API payload grep-style no forbidden tokens.
- Frontend: Notifications tests assert no \\b(FAIL|WARN|PASS)\\b in document; legacy-style mock shows safe label.
