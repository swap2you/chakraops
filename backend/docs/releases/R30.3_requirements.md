# R30.3 — Attach readiness pack to Journal/Ticket (NO GIT)

**NO GIT.** Manual-only. No broker automation. No schedulers/background jobs.

## Non-negotiables

- Manual-only. No broker automation. No schedulers/background jobs.
- Do NOT write out/decision_latest.json.
- Decision artifacts remain code-only; never persist prose/UI strings in decision artifacts.
- UI must never display raw FAIL/WARN/PASS or FAIL_/WARN_ substrings.
- Attachment must contain no forbidden tokens and no secrets. Deterministic ordering and stable outputs.

## Goal

Allow operator to optionally attach a sanitized readiness pack (as JSON bundle, not ZIP) to a journal entry when recording/saving from Trade Ticket, and later download it from the Journal UI. Store in SQLite (data/), not in out/.

## Scope

### Backend: Database

- **journal_attachments** table: id TEXT PRIMARY KEY, journal_entry_id TEXT NOT NULL, kind TEXT NOT NULL, content_json TEXT NOT NULL, created_at_utc TEXT NOT NULL. Index on journal_entry_id.

### Backend: API

- **POST /api/ui/journal/from-ticket** (extend): Request boolean **attach_readiness_pack** (default false). If true: build readiness pack JSON bundle (manifest, readiness, system_health_subset, notes) via same logic as R30.2; sanitize with sanitize_json_for_export; insert into journal_attachments. Journal entry creation remains deterministic; attachment insert after journal insert succeeds.
- **GET /api/ui/journal/entry/{id}/attachment/readiness-pack**: Response application/json with attached JSON bundle. 404 with safe message if missing (no FAIL/WARN/PASS).
- **GET /api/ui/journal** (list): Each entry includes **has_readiness_pack** boolean when attachment exists.
- None of these endpoints write out/decision_latest.json.

### Backend tests: test_r303_journal_readiness_pack_attachment.py

- test_attach_readiness_pack_persists_sanitized_json
- test_attachment_download_endpoint_returns_same_json
- test_attachment_has_no_forbidden_tokens
- test_attachment_does_not_write_decision_latest
- test_attach_false_creates_no_attachment (backward compat)

### Frontend

- **TradeTicketPage:** Checkbox "Attach readiness pack to journal entry" (default OFF) in save/record section. When saving, include attach_readiness_pack and mode in request payload. No forbidden tokens in UI.
- **Journal UI:** When entry has has_readiness_pack, show "Download readiness pack" button; clicking calls GET attachment and triggers file download as JSON (filename readiness_pack_<symbol>_<journal_entry_id>.json). If not exists: show nothing.

### Frontend tests

- TradeTicketPage: checkbox toggles; payload includes attach_readiness_pack=true when checked; no forbidden tokens.
- Journal page: when mocked entry has has_readiness_pack, "Download readiness pack" button appears and click calls download; no forbidden tokens.
