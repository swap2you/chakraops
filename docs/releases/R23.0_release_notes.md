# Release R23.0 — Shares Positions + Symbol Shares Tab + Portfolio Wiring

**Date:** 2026-02  
**Goal:** Let users record shares holdings (“I have 50 shares of NVDA”), show shares plan context on Symbol page, compute CC eligibility from total shares (holdings + share_positions), and show shares positions in Portfolio with basic MTM/PnL. Shares recommendations remain advisory only; no broker order placement.

---

## Scope

- **Part A — DB:** New table `share_positions` (id, account_id, symbol, quantity, avg_cost, opened_at, notes, created_at, updated_at); unique (account_id, symbol). CRUD in `holdings_db.py`. `get_total_shares_for_evaluation()` merges holdings + share_positions for CC eligibility (≥100 shares).
- **Part B — API:** GET/POST/DELETE `/api/ui/shares/positions` and `/api/ui/shares/positions/{symbol}`; portfolio and portfolio/mtm include `shares_positions`; symbol-diagnostics includes request-time `shares_plan` (Part D contract) and `shares_position`.
- **Part C — UI:** Symbol page Options | Shares tab; Shares tab: eligibility (safe label), MTF/targets/hold-time refs, Your Shares Position panel, Add/Update Shares Position modal. Portfolio: Shares Positions card (Symbol, Qty, Avg cost, Last price, Market value, Unrealized PnL).
- **Part D — Shares plan contract:** symbol-diagnostics `shares_plan` has eligible, eligibility_codes, spot, support_resistance, targets, hold_time, indicators_used, as_of_inputs (machine codes only; UI maps to safe text). Not persisted in decision_latest.json.
- **Out of scope:** Broker order placement; persisting shares_plan or diagnostics in decision artifacts.

---

## API changes

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/ui/shares/positions?account_id=...` | List share positions for account. |
| GET | `/api/ui/shares/positions/{symbol}?account_id=...` | Single position (404 if none). |
| POST | `/api/ui/shares/positions/{symbol}` | Upsert. Body: `{ account_id, quantity, avg_cost?, opened_at? }`. |
| DELETE | `/api/ui/shares/positions/{symbol}?account_id=...` | Delete position. |

- **GET /api/ui/portfolio** — response includes `shares_positions[]` (symbol, quantity, avg_cost, last_price, market_value, unrealized_pnl, updated_at).
- **GET /api/ui/portfolio/mtm** — response includes `shares_positions[]` (same shape).
- **GET /api/ui/symbol-diagnostics** — response includes `shares_plan` (request-time; Part D structure) and `shares_position` (current position for symbol if any).

---

## UI changes

- **Symbol (Execution Console):** Tab control “Options” | “Shares”; default Options. Shares tab: eligibility label, MTF/targets/hold-time references, “Your Shares Position” (qty, avg_cost, last updated or “No shares position recorded”), “Add / Update Shares Position” button → modal (Quantity, Avg cost, Opened date), Save/Delete.
- **Portfolio:** “Shares Positions” card/table when `shares_positions.length > 0`: Symbol (link to Symbol page), Qty, Avg cost, Last price, Market value, Unrealized PnL.

---

## Data / persistence

- **New:** SQLite table `share_positions` in `account.db` (same DB as holdings). No new keys in decision_latest.json; shares_plan and shares_position are request-time only.
