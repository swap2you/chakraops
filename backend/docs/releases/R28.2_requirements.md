# R28.2 — Safe labels in UI-facing runtime state files (out/)

**Branch:** release/R28.2 (operator creates)  
**Manual-only.** No broker automation.

## Goal

Eliminate raw FAIL/WARN/PASS tokens from UI-facing runtime state files in `out/` (e.g. `out/portfolio_risk_notify_state.json`, `out/mark_refresh_state.json`). Persist only safe status and label; UI and system-health must never expose raw codes.

## Non-goals

- No change to decision artifact schema or persistence.
- No change to evaluation/reason codes inside decision artifacts (those remain code-only as before).

## Non-negotiables

- Decision artifacts remain code-only; no prose/UI strings; no raw FAIL_/WARN_ in decision artifacts.
- UI must never display raw FAIL/WARN/PASS words or codes (safe labels only).
- Repo hygiene: out/ only whitelisted artifacts; no secrets; gates + verification notes required.

## Scope

### A) UI-facing out/ state writers

- **out/mark_refresh_state.json**  
  Writer: `write_mark_refresh_state` in `mark_refresh_state.py`.  
  - Persist `status` (OK | Blocked | Degraded | Review) and `status_label` (e.g. "OK", "No update", "Partial update").  
  - Do not persist literal "PASS", "FAIL", or "WARN".  
  - Loader returns safe fields; backward compat for old files that had `last_result` (normalize on read).

- **out/portfolio_risk_notify_state.json**  
  Writer: `_save_state` in `risk_notify_state.py`.  
  - Persist `status` and `status_label` only (no `last_status` = FAIL/WARN).  
  - Backward compat: readers accept old `last_status` and normalize for display.

- **Normalization:** Shared helper `normalize_runtime_status(raw)` → (safe_status, safe_label).  
  PASS → (OK, OK); FAIL → (Blocked, Limit breach); WARN → (Degraded, Advisory).  
  Mark-refresh-specific labels: FAIL → (Blocked, No update), WARN → (Degraded, Partial update).

### B) Backend tests

- New tests in `test_r282_runtime_state_safe_labels.py`:  
  - Writer output (both state files) contains no forbidden tokens (FAIL, WARN, PASS).  
  - No write to `out/decision_latest.json` from these writers.  
  - Backward compat: load old schema via .get; returned payload is safe.

### C) Frontend

- System Diagnostics (and any UI that shows these blocks) uses only safe fields (`status`, `status_label`).  
- No raw FAIL/WARN/PASS in rendered document for mark_refresh and portfolio_risk_notifier.  
- Frontend test: mock system-health with safe payload; assert no `/\bFAIL\b/`, `/\bWARN\b/`, `/\bPASS\b/` in document.

- [ ] After portfolio risk notify, `out/portfolio_risk_notify_state.json` contains only safe `status` / `status_label`.
- [ ] System Health API returns only safe values for `mark_refresh` and `portfolio_risk_notifier`.

- [ ] Backend and frontend gates pass; evidence in `out/verification/R28.2/notes.md`.
