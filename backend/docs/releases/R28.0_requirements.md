# R28.0 — Paper write mirror + reconcile health + Positions UI upgrades

**Branch:** release/R28.0  
**Manual-only.** No broker automation.

## Goal

- Mirror paper position open/close writes into the unified positions DB (positions_open / positions_closed) with idempotent upserts and deterministic ordering.
- Add system-health block `positions_unified_reconcile` (paper source vs unified DB counts; safe status OK/Review).
- Upgrade Positions page: Source column (LIVE/PAPER), Mark/Unrealized for paper when API provides, safe labels only, Ticket/Journal/Paper close links.

## Non-goals

- No broker automation; no new persistence of decision artifacts or prose/UI strings.
- No raw FAIL_/WARN_ in API or UI.
- No writes to out/decision_latest.json from unified positions flows.

## Non-negotiables

- Decision artifacts remain code-only; never persist prose/UI strings or raw FAIL_/WARN_.
- UI and API: safe labels only; never show raw FAIL/WARN words or codes.
- Determinism: unified list stable ordering and stable IDs; idempotent mirror keys (stable position identifiers, not timestamps alone).
- Manual-only; gates pass; evidence in out/verification/R28.0/notes.md + UAT checklist.

## Detailed scope

1. **Backend — paper write mirror**
   - Hook into existing paper open/close write paths (paper execute + paper close workflow).
   - Helper (in positions_unified_store or dedicated module) to upsert unified rows for paper positions:
     - Open: upsert into positions_open.
     - Close: upsert into positions_closed.
   - Idempotent keys (stable position identifiers); preserve deterministic ordering semantics.

2. **Backend — reconcile health**
   - System-health block `positions_unified_reconcile`:
     - Counts from paper source vs unified DB.
     - Safe label status: `OK` or `Review` (no FAIL/WARN words or codes anywhere).

3. **Frontend — Positions UI upgrades**
   - Source column (LIVE/PAPER) if not already explicit.
   - For open paper rows: show Mark and Unrealized when API provides; else "—".
   - Safe labels only; no FAIL/WARN in UI.
   - Links: Ticket, Journal, Paper close where applicable.

4. **Tests**
   - Backend: paper open/close mirror idempotent; reconcile health safe labels; no decision_latest writes; retain R27.9 determinism/filter tests.
   - Frontend: new columns render; mark/unrealized for paper when present; filters work; no /\bFAIL\b/ or /\bWARN\b/ in document.
