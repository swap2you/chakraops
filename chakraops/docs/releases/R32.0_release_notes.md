# R32.0 Release Notes — Market Data, Earnings, Universe, Freshness (PARTIAL)

_Program R31–R35, milestone 2 on `release/R31-R35-program`._

## Summary

R32.0 delivers the Critical security remediation (C-1): the ORATS API token is no longer stored in tracked source and is resolved from the environment only. Remaining R32.0 data-reliability outcomes are scoped but not yet implemented and are explicitly tracked as pending.

## Delivered (C-1)

- `chakraops/app/core/config/orats_secrets.py`: removed hardcoded token; environment-only resolution; added `get_orats_token(required=False)` that fails loudly (no value leaked) when a required token is missing. `ORATS_API_TOKEN` module attribute retained (env-resolved) for backward compatibility and test patches.
- `chakraops/app/api/server.py`: startup reads token from env; logs a redacted presence boolean; warns loudly when missing; ORATS boot probe reports `UNAVAILABLE` (not a fake `OK`) when the token is absent.
- Fixed misleading "hardcoded" wording in `scripts/orats_smoke.py` and `README.md`.
- Verified `.gitignore` ignores `.env`/`*.env`; `.env.example` placeholder present (no real value).
- Added `tests/test_r320_orats_secret_env_only.py` (6 tests).

## Confirmed pre-existing (no change needed)

- Fail-fast behavior with no silent options-data fallback.
- Redacted read-only smoke path (`probe_orats_live`).
