# R25.7 — Earnings Advisory Correctness + Consistency (Stabilization)

## Scope

Stabilization release: ensure earnings data is evaluated consistently, decision artifact never contains `EARNINGS_NOT_EVALUATED`, implied move scaling is applied exactly once, and UI shows sensible values with no bad strings (no "00", "0000-00-00", raw FAIL/WARN).

## Non-negotiables

- **Decision artifacts code-only** — No prose/UI strings; no FAIL_/WARN_ persisted anywhere.
- **UI** — Never display raw FAIL/WARN or FAIL_/WARN_ tokens.
- **Determinism** — Universe eval snapshot and per-symbol recompute must match for earnings fields.
- **SDLC** — Backend pytest, frontend tests, frontend build pass; tails and UAT in `out/verification/R25.7/notes.md`.

## Goals

1. **Earnings consistency**
   - After an eval run completes, `decision_latest.json` `earnings_by_symbol` must **NOT** contain `status_code` `"EARNINGS_NOT_EVALUATED"`.
   - Acceptable statuses: **OK**, **Unavailable**, **Stale** (and **EARNINGS_BLOCKED** where applicable; never EARNINGS_NOT_EVALUATED).
   - If ORATS is unavailable, use **Unavailable**.
   - Per-symbol recompute uses the same snapshot earnings fields unless force refresh is explicitly requested.

2. **Implied earnings move**
   - Apply scaling rules exactly once (single source of truth in `app.core.orats.earnings`).
   - UI shows a sensible percent (e.g. 7.2%); never "0"/"00" unless value is truly 0 and status OK (prefer null over misleading zeros).

3. **UI**
   - Hero earnings pill only when status OK and next date + earnings_days valid.
   - Risk flags show "Unavailable" when status not OK.
   - Never render "0000-00-00" or "Earnings: 00".

4. **Tests**
   - Backend: no `EARNINGS_NOT_EVALUATED` post-eval; determinism across recompute.
   - Frontend: no bad strings; implied move formatting.

## Verification

- Gate tails (pytest, frontend test, frontend build) and UAT checklist in `out/verification/R25.7/notes.md`.
- Grep: `decision_latest.json` contains no `EARNINGS_NOT_EVALUATED` and no `FAIL_`/`WARN_`.
