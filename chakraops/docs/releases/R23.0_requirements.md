# R23.0 — Shares Positions + Symbol Shares Tab + Portfolio Wiring

**Date:** 2026-02  
**Goal:** Let users record shares holdings (“I have 50 shares of NVDA”), show shares plan context on Symbol page, compute CC eligibility from total shares (holdings + share positions), and show shares positions in Portfolio with basic MTM/PnL. Shares recommendations remain advisory only; no broker order placement.

---

## Objectives

- Persist **shares positions** in SQLite (separate from options positions and from legacy “holdings” manual entry).
- **CC eligibility:** Use total_shares = holdings_shares + share_positions_shares (≥100 for CC).
- **Symbol page:** Add “Shares” tab with eligibility verdict (safe label), MTF levels, Targets & hold-time, “Your Shares Position” panel, and Add/Update Shares Position flow.
- **Portfolio page:** Add “Shares Positions” card (Symbol, Qty, Avg cost, Last price, Market value, Unrealized PnL).
- **API:** CRUD for share positions; extend portfolio and symbol-diagnostics with shares data (request-time only; no persistence in decision artifacts).

## Non-goals

- Broker order placement for shares.
- Persisting shares_plan or any prose/diagnostics in decision_latest.json.
- Displaying raw FAIL_* / WARN_* codes in UI.

## Acceptance criteria

- [ ] User can add/update/delete a shares position per symbol from Symbol page (Shares tab) and see it on Portfolio.
- [ ] CC eligibility uses total shares (holdings + share_positions) ≥ 100.
- [ ] Symbol-diagnostics response includes request-time `shares_plan` and current `shares_position` (if any); no new keys in decision JSON.
- [ ] Portfolio and portfolio/mtm include shares_positions summary (qty, avg_cost, last_price, market_value, unrealized_pnl).
- [ ] Backend tests: share_positions CRUD, API endpoints, CC eligibility with share_positions.
- [ ] Frontend tests: Symbol Shares tab, Portfolio Shares card; no raw FAIL_/WARN_ in Shares UI.
- [ ] All gates pass and recorded in out/verification/R23.0/notes.md.

## UI/UX requirements

- **Symbol page:** Tab control “Options” | “Shares”; default Options. Shares tab: eligibility (safe label), MTF levels, Targets & hold-time, “Your Shares Position” (qty, avg_cost, market value, unrealized pnl, last updated or “No shares position recorded”), “Add / Update Shares Position” button opening modal (Quantity required, Avg cost optional, Opened date optional); Save → POST; Delete → DELETE. No raw FAIL_/WARN_.
- **Portfolio page:** “Shares Positions” card/table: Symbol (link to Symbol page), Qty, Avg cost, Last price, Market value, Unrealized PnL. Existing Holdings and Positions unchanged.

## API contracts

- `GET /api/ui/shares/positions?account_id=...` → list positions.
- `GET /api/ui/shares/positions/{symbol}?account_id=...` → single position (404 if none).
- `POST /api/ui/shares/positions/{symbol}` body `{ account_id, quantity, avg_cost?, opened_at? }` → upsert, return position.
- `DELETE /api/ui/shares/positions/{symbol}?account_id=...` → delete.
- **Portfolio:** `/api/ui/portfolio` and `/api/ui/portfolio/mtm` include `shares_positions` (or equivalent) with qty, avg_cost, last_price, market_value, unrealized_pnl.
- **Symbol-diagnostics:** Response includes `shares_plan` (request-time; structure per Part D) and `shares_position` (current position for symbol if any).

## DB schema

- **Table:** `share_positions` (in account.db).
- **Columns:** id (uuid/text PK), account_id (text, required), symbol (text, required), quantity (int, required), avg_cost (real, nullable), opened_at (iso timestamp text, nullable), notes (text, nullable), created_at (text), updated_at (text).
- **Unique:** (account_id, symbol) — one row per account+symbol.

- **Frontend:** Symbol Shares tab renders; Add/Update shares calls mocked API; Portfolio Shares positions table from mocked API; no raw FAIL_/WARN_ in Shares tab.
