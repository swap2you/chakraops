# R23.4.8 — Score Used + Plain-English Explainability

**Goal:** Clearly state which score is used (raw vs final capped) and why; add plain-English explanation for hold-time (session = one trading day, rough estimate, not a promise). Frontend-only; no backend or layout redesign.

---

## Acceptance criteria

### A) SymbolDiagnosticsPage — Score breakdown card
- Line: **"Score used: Final score (capped)"** when `score_caps.applied_caps.length > 0`.
- Line: **"Score used: Raw score (uncapped)"** when `applied_caps` is empty.
- Add 1–2 sentence plain-English explanation under that line:
  - If capped: explain regime cap limits final score even if raw is high (e.g. liquidity/strategy fit).
  - If uncapped: explain final equals raw since no caps applied.
- Reuse existing fields (raw_score, final_score, applied_caps).

### B) UniversePage — Score tooltip
- Tooltip first line:
  - **"Score used: Final (capped)"** if caps exist.
  - **"Score used: Raw (uncapped)"** if no caps.
- Keep existing "Capped by: … before→after" line(s).

### C) Hold-time (Symbol Diagnostics)
- Define **session = one trading day**.
- Plain-English: hold-time is rough estimate based on ATR and distance to T1: how many trading days to reach T1 if price moves ~1 ATR per day.
- Mention it is not a promise.
- Targets & hold-time card + INFO drawer; no formula/calculation changes.

### D) Tests
- When applied_caps present: assert **"Score used: Final score (capped)"**.
- When applied_caps empty: assert **"Score used: Raw score (uncapped)"**.
- Hold-time block/drawer: assert text includes "session" / "one trading day" and plain-English sentence (e.g. not a promise).
- Existing tests remain passing.
