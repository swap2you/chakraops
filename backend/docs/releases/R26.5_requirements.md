# R26.5 — Monthly close + performance pack (journal-driven)

## Scope

Generate a deterministic "close pack" per month under `data/reports/<YYYY-MM>/` (not `out/`): JSON report, CSV report, journal export CSV, and a short summary.txt. UI panel on Reports page to generate and download. State stored in SQLite for last-run display.

## Non-negotiables

- Decision artifacts code-only; no prose/UI strings; no raw FAIL_/WARN_ in decision_latest.json.
- UI safe labels only; no FAIL/WARN words.
- Deterministic: same journal data → same close pack output (ordering and content).
- No broker automation.
- Gates + evidence in out/verification/R26.5/notes.md + UAT.

## 1) Monthly Close Pack (backend)

- **POST /api/ui/reports/monthly/close?month=YYYY-MM**  
  Generates pack under `data/reports/YYYY-MM/`:  
  `monthly_report.json`, `monthly_report.csv`, `journal_export.csv`, `summary.txt`.  
  If folder exists, overwrite deterministically (same ordering).
- **monthly_report.json**: totals (realized_pl, fees, trade_count, win_rate), by_strategy, winners/losers arrays, optional guardrails snapshot (safe numeric only), generated_ts, month.
- **summary.txt**: 6–10 lines, templated; no FAIL/WARN.

## 2) Persistence

- SQLite table **monthly_close_state**: month, generated_ts, paths_json.  
  So UI can show last run without scanning filesystem. Store under `data/` (e.g. same DB as checklist or dedicated).

## 3) Download endpoints

- **GET /api/ui/reports/monthly/close/files?month=YYYY-MM**  
  Returns available files + sizes.
- **GET /api/ui/reports/monthly/close/download?month=YYYY-MM&file=<name>**  
  Streams file; validate `file` against allowlist (monthly_report.json, monthly_report.csv, journal_export.csv, summary.txt).

## 4) Monthly Close UI (Reports page)

- Panel: "Monthly Close" with button "Generate close pack", last generated_ts, file paths (relative), and download links (JSON / CSV / TXT) or "Download bundle" (zip). If zip is complex, use separate download links.

## 5) Tests

- Backend: close pack in temp dir (override base path), deterministic ordering, download allowlist, no FAIL_/WARN_ in JSON responses.
- Frontend: Reports page Monthly Close panel with mocked APIs; Generate triggers mutation; no FAIL/WARN in DOM.
