# R28.1 — Live close/roll mirror + reconcile advisory notification + System Health visibility

**Branch:** release/R28.1 (operator creates)  
**Manual-only.** No broker automation.

## Goal

- Mirror LIVE “record close” and “record roll” into the unified positions DB (advisory/mirror-only; legacy remains source-of-truth). Idempotent writes.
- When `positions_unified_reconcile` status is “Review”, create ONE deduped advisory notification (safe labels only; transition-aware).
- Add minimal UI visibility for the reconcile block on the System Health / System Diagnostics page (status OK/Review + counts; no FAIL/WARN).
- Tests lock determinism, idempotency, no FAIL_/WARN_ in payload/DOM, and no decision artifact writes.

## Non-goals

- No broker automation; no new persistence of decision artifacts or prose/UI strings.
- No raw FAIL_/WARN_ in API or UI.
- No writes to out/decision_latest.json from unified positions or notification flows.

## Non-negotiables

- Decision JSON artifacts must remain code-only; canonical out/decision_latest.json + archived history.
- Never persist prose/UI strings/panels in decision artifacts.
- Never persist raw FAIL_/WARN_ tokens anywhere in decision artifacts.
- UI must never display raw FAIL/WARN words/codes (safe labels only).
- Determinism: universe evaluation vs per-symbol recompute must match; snapshot semantics where needed; stable deterministic ordering.
- Repo hygiene: out/ only whitelisted artifacts; no secrets; no noisy runtime artifacts committed.
- SDLC gates must pass and be recorded for sign-off (backend pytest, frontend test + build; evidence in out/verification/R28.1/notes.md).

## Scope

1. **Backend — live close/roll mirror**
   - When live close or roll is recorded via existing UI/API (shares close, options close, options roll), mirror the closed (and for roll, the new open) row into unified DB.
   - Idempotent: stable IDs from source (e.g. position_id, closed row id); no duplicates on repeated invocation.
   - For close: remove open row from positions_open if applicable; upsert into positions_closed.
   - For roll: mirror closed position to positions_closed; mirror new open position to positions_open.

2. **Backend — reconcile advisory notification**
   - Use `get_positions_unified_reconcile_health()` (R28.0). If status == "Review":
     - Create or ensure ONE advisory notification (safe label only; no FAIL/WARN in message or payload).
     - Deduped: one active (NEW or ACKED) notification keyed by type; transition-aware (do not create if one already exists).
   - If status == "OK": do not spam; optionally leave existing advisory as-is (no auto-archive required unless consistent with notification lifecycle).

3. **Backend — trigger for notification**
   - Trigger reconcile notification after live close/roll mirror in the same request (re-evaluate reconcile after mirror; create notification if Review and not already present). System-health remains read-only.

4. **Frontend — System Health visibility**
   - On the page that shows system-health (e.g. System Diagnostics): add a small “Unified Positions Reconcile” section showing status (OK / Review), counts (paper_open, paper_closed, unified_open_paper, unified_closed_paper or equivalent). No FAIL/WARN words.

5. **Tests**
   - Backend: live close mirror idempotent; reconcile Review creates single notification (deduped); system-health and API responses contain no FAIL_/WARN_; mirror does not write decision_latest.
   - Frontend: reconcile block renders when present in mocked system-health; document has no /\bFAIL\b/ or /\bWARN\b/.
