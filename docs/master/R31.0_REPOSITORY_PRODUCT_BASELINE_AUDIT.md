_Program: R31–R35 (single branch `release/R31-R35-program`). Milestone: R31.0. Risk level: 2 (read-only audit/planning). No source changes._

---

## 1. Executive Summary

ChakraOps is a manual-only options-wheel decision-support system: a FastAPI backend (`chakraops/`) that evaluates a symbol universe through a staged decision pipeline using ORATS as the sole options-data provider, and a React/Vite/TypeScript frontend (`frontend/`) that presents decisions, positions, journal, and diagnostics. The product is functionally rich but carries operational debt: duplicated subsystems (two API surfaces, two decision/signal stacks, two evaluation stores, two journals), a broken frontend import layer (`@/data/*`), a committed ORATS credential, an inert macro-event calendar, and stale roadmap documentation.

This baseline establishes the trusted architecture map and feeds the R31.0 defect register and execution blueprint that govern R32–R35.

## 3. Backend Architecture (`chakraops/`)

### 3.1 Entry points

| Path | Role |
|------|------|
| `scripts/run_api.py` | Primary API entry; loads `.env`, runs uvicorn on `app.api.server:app` |
| `app/api/server.py` | FastAPI app factory: lifespan, CORS, background schedulers, legacy `/api/*` routes |
| `run_evaluation.py` | CLI universe evaluation |
| `main.py` | Legacy orchestrator (regime/Slack/position mgmt) — not the golden path |

### 3.2 API surfaces (duplication)

- `app/api/ui_routes.py` — secured `/api/ui/*` React surface (~90 routes), optional `UI_API_KEY` + `x-ui-key`.
- `app/api/copilot.py` — `/api/ui/copilot`.
- `app/api/server.py` — legacy `/api/*` (`/api/view/*`, `/api/ops/*`, `/api/trades/*`, `/api/portfolio/*`, etc.) that overlap the `/api/ui/*` surface.

### 3.3 Decision pipeline (canonical golden path)

```
evaluation_service_v2.evaluate_universe()
  └─ universe_evaluator.run_universe_evaluation_staged()
       └─ staged_evaluator.evaluate_stage1()  (STAGE1_TOP_K=20)
            └─ eligibility_engine.run() → mode_decision: CSP | CC | NONE
                 └─ staged_evaluator.evaluate_symbol_full()  (CONTRACT_SELECTION_TOP_N=3)
                      ├─ options/v2/csp_chain_v2.py  (PUT OTM)
                      ├─ options/v2/cc_chain_v2.py   (CALL OTM)
                      └─ trade_construction/engine.py (iron condor gating IV 30–70)
                 └─ eval/decision_artifact_v2.py (assign_band, DecisionArtifactV2)
                 └─ eval/scoring.py (compute_score_breakdown, build_rank_reasons)
                 └─ ranking/service.py (rank_opportunities limit=5; dashboard top 5–7)
  → out/decision_latest.json (single decision artifact via evaluation_store_v2.py)
```

Parallel/legacy stacks (candidates for consolidation): `app/signals/` (CSP/CC generators + `signals/scoring.py`), `app/core/scoring/ranking.py` (informational), `app/core/heartbeat.py` (parallel CSP scoring).

### 3.4 Strategy modules

| Strategy | Files |
|----------|-------|
| CSP | `eligibility/eligibility_engine.py`, `options/v2/csp_chain_v2.py`, `signals/csp.py`, `core/engine/csp_trade_engine.py`, `options/contract_selector.py` |
| CC | `eligibility_engine.py` (≥100 shares), `options/v2/cc_chain_v2.py`, `signals/cc.py` |
| Share buy | `core/shares/shares_plan.py` (`compute_shares_eligibility`) |
| Cash / NONE | eligibility `mode_decision == "NONE"`; ranking skips non-ELIGIBLE |
| Position actions | `core/action_engine.py` (HOLD/CLOSE/ROLL/ALERT) |
| Wheel lifecycle | `core/wheel/{state_store,next_action,repair,actions_store}.py` |

### 3.5 Scoring / banding / sizing

- Score: `eval/scoring.py` (0–100 composite: data quality, regime, liquidity, strategy fit, capital efficiency).
- Bands: `eval/confidence_band.py` (A≥78) vs `eval/decision_artifact_v2.py` (`TIER_A_MIN=80`) — **inconsistent thresholds**.
- Sizing: `scoring/position_sizing.py` (informational), `portfolio/sizing_r260.py` (budget/reserve/caps), `portfolio/risk_proxy_r261.py`, `portfolio/risk.py` (`would_exceed_limits`).

### 3.6 ORATS integration

- Canonical facade: `app/core/data/orats_client.py` re-exporting `app/core/orats/*`.
- Endpoint manifest: `app/core/orats/endpoints.py` (`/datav2/cores`, `/strikes`, `/strikes/options`, `/live/strikes`, `/live/summaries`, `/ivrank`, `/hist/dailies`).
- Separate client: `app/core/options/providers/orats_client.py` (env-token, 429 retry).
- Credential inputs (names only): `ORATS_API_TOKEN`, `ORATS_API_KEY`, `ORATS_DATA_MODE` (`delayed`/`live`/`live_derived`), `ORATS_API_BASE`, `DEBUG_ORATS`; **plus a hardcoded token in `app/core/config/orats_secrets.py`** (Critical — see defect register).
- Errors: `OratsUnavailableError`, `OratsCoreError`, `OratsDataUnavailableError`, `OratsAuthError`; fail-fast, "no silent fallbacks" comment in chain pipeline.
- Freshness/cache: `core/data/cache_policy.py` (cores/strikes/quotes 60s; iv_rank 6h; earnings 24h), `cache_store.py`, `EVAL_SNAPSHOT_VALID_MINUTES` (default 10).

### 3.7 Universe

- Base: `config/universe.csv`; overlay `out/universe_overrides.json` (`universe_overrides.py`); effective set = (CSV ∪ added) − removed via `app/api/data_health.py`.
- Cadence/tiers: `universe/universe_manager.py` + `artifacts/config/universe.json`; scheduler `UNIVERSE_EVAL_MINUTES` (default 30); nightly `NIGHTLY_EVAL_*`. **No dedicated weekly refresh job** (interval/tier-driven). CSV loaded at import — requires restart unless overlay used.

### 3.8 Earnings / events

- ORATS earnings advisory: `core/orats/earnings.py` (`fetch_earnings_advisory`) — request-time, does not block eligibility.
- Earnings gate: `core/environment/earnings_gate.py` (blocks within block window).
- Macro calendar: `core/environment/event_calendar.py` is a **stub returning `[]`**; `macro_event_gate.py` is wired but inert in production.

### 3.9 Persistence

SQLite: `app/data/chakraops.db` (regime/alerts/trades/portfolio/universe/csp_evaluations/...), `data/journal.db`, `out/account.db`, `data/positions.db`, `data/paper.db`, `data/universe_admin.db`, `data/monthly_close_r265.db`, `data/execution_log_r269.db`, `data/checklist_r264.db`, `data/backtest.db`. `DATA_DIR` env override supported.

File stores under `out/`: `decision_latest.json`, `decision_frozen.json`, `decisions/<symbol>/*.json`, `notifications.jsonl`, `slack_status.json`, `universe_overrides.json`, `trades/`, `evaluations/`, `lifecycle/lifecycle_log.jsonl`, `snapshots/*_eod/`.

Debt: split persistence across `app/data/` vs `data/` vs `out/`; dual journals (SQLite `journal_store.py` vs file `journal/store.py`); dual eval stores (v1 `evaluation_store.py` vs v2 `evaluation_store_v2.py`).

### 3.10 Backtest

- `app/backtest/engine.py` — Phase 5 snapshot CSV simulation (CSP/CC, no live calls; simplified premium `strike*0.005`).
- `app/core/backtest/backtest_runner_r275.py` — journal replay from `journal.db`.
- Live/sim separation via `app/core/run_mode.py` (`DRY_RUN|PAPER_LIVE|LIVE`) and UI `_validate_live_artifact()` rejecting mock/scenario sources.

### 3.11 Jobs / scheduling / observability

In-process daemon threads in `server.py`: universe eval (`UNIVERSE_EVAL_MINUTES`), nightly eval (19:00 ET), EOD freeze (15:58 ET), EOD chain snapshot (16:05 ET). Observability: `core/system/watchdog.py` (`SCHEDULER_STALLED`), `core/system_health.py`, `/api/ui/system-health`, `/api/ops/scheduler-status|nightly-status|data-health`.

### 3.12 Notifications

Slack: `core/alerts/slack_notifier.py`, `slack_dispatcher.py` (channels signals/daily/data_health/critical), status `out/slack_status.json`. UI store: `app/api/notifications_store.py` → `out/notifications.jsonl` (NEW→ACKED→ARCHIVED, SHA dedupe). Safe labels: `core/notifications/notification_safe_labels.py`.

### 3.13 Tests

159 test files (~877 `def test_` functions) under `chakraops/tests/`; release-tagged (`test_r2xx_*`, `test_r3xx_*`), `tests/_core/`, `tests/api/`, `tests/fixtures/`. Gaps: real macro calendar, live-ORATS e2e, dual-store drift, legacy `main.py`, band-threshold regression.

## 4. Frontend Architecture (`frontend/`)

### 4.1 Routing (18 live routes, `src/app/App.tsx`)

`/` Dashboard, `/universe`, `/symbol-diagnostics`, `/system`, `/notifications`, `/journal`, `/learn`, `/ticket`, `/today`, `/weekly`, `/reports`, `/backtest`, `/paper`, `/universe-admin`, `/universe-health`, `/portfolio`, `/positions`, `/wheel` (feature-gated), `*`→`/`. Nav: `src/layout/Sidebar.tsx`.

### 4.2 Orphans / dead routes

- 9 orphan pages (implemented, unrouted): `AnalysisPage`, `AnalyticsPage`, `HistoryPage`, `DiagnosticsPage`, `DecisionPage`, `AccountsPage`, `TrackedPositionsPage`, `StrategyPage`, `PipelinePage`.
- 2 unmounted nav components with 10 stale paths: `CommandBar.tsx`, `CommandPalette.tsx`.
- Overlapping clusters: symbol (SymbolDiagnostics/Analysis), universe (Universe/Analytics), positions (Positions/Portfolio/TrackedPositions/Paper/Wheel), diagnostics (System/Diagnostics), daily ops (Today/Dashboard), accounts (Portfolio/Accounts).

### 4.3 API layer

- Primary: `src/api/client.ts` + `src/api/queries.ts` (~70 react-query hooks) → `/api/ui/*` (proxy to :8000); `ApiError`, no silent fallback.
- **Dual API layer (correction):** a second layer `src/data/` **does exist** (`apiClient.ts`, `endpoints.ts`, `pipelineDetails.ts`, `source.ts`, `uiApiClient.ts`) and is imported by legacy/orphan modules via `@/data/*`. `tsc -b` compiles cleanly and the build passes — these imports are NOT broken. The issue is duplication (two API layers), a consolidation candidate, not a build defect. (An earlier exploration pass incorrectly reported `src/data/` as missing; the R31.0 build evidence refutes that.)
- Mixed static/dynamic imports of `@/api/queries`/`client` (in `queries.ts`, `PositionsPage.tsx`, `SystemDiagnosticsPage.tsx`) → confirmed Vite reporter warning at build time (build still succeeds).

### 4.4 Known warnings

- Nested `<tr>`: `TableHeader` already renders `<tr>`; wrapping `TableRow` inside it occurs in `PortfolioPage.tsx`, `JournalPage.tsx`, `ReportsPage.tsx`, `BacktestPage.tsx`, `UniverseAdminPage.tsx`.
- Bundle size: no `chunkSizeWarningLimit` set (default 500 kB); large modules `SymbolDiagnosticsPage`, `SystemDiagnosticsPage`, `queries.ts`.

### 4.5 Trading-safety UI

Sanitizers: `utils/sanitizeDisplay.ts` (`sanitizeForDisplay`, `safeForReadinessDisplay`), `lib/safeLabels.ts` (`gateStatusToLabel`), `reasons/parsePrimaryReason.ts`, `components/ui/Badge.tsx` `StatusBadge`. Leak risks (raw `primary_reason`/codes): `UniversePage.tsx`, `SymbolDiagnosticsPage.tsx` debug tooltips, `TradeTicketPage.tsx` readiness codes, orphan `AnalyticsPage.tsx`.

### 4.6 Tests

~33 spec files, ~325 `it()` (≈308 unit + ~11 live schema + ~7 live e2e). Gaps: orphan pages, App route table, CopilotPanel/`@/data` breakage, nested-`<tr>` structure, Universe primary_reason forbidden-token test, no Playwright/Cypress e2e.
