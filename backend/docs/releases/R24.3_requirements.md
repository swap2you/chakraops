# R24.3 — Position-Aware Lifecycle Alerts for Tracked Option Positions + wheel_state Retention

## Objective

Deliver request-time lifecycle computation for **tracked option positions** (CSP/CC from positions service), surface structured lifecycle fields in action-needed API, Slack, and Dashboard; and add deterministic retention for `wheel_state.json` `linked_position_ids` to prevent unbounded growth. No new persistence into decision artifacts.

## Non-negotiables (must not regress)

- Decision JSON artifacts remain code-only. Canonical `out/decision_latest.json` and archived history only.
- Never persist prose/UI strings/panels or raw FAIL_/WARN_ in decision artifacts.
- UI must never display raw FAIL_/WARN_; API must not return them in UI payloads.
- SDLC gates (pytest, frontend test, frontend build) must pass; raw outputs pasted in `out/verification/R24.3/notes.md`.
- Repo hygiene: `out/` whitelist only; no secrets; no scratch.
- Deterministic behavior: same inputs → same lifecycle outputs; snapshot semantics where applicable.

## Scope

### Part A — Request-time lifecycle for tracked option positions

- **Inputs (from position + optional quote):** position entry credit (open_credit/credit_expected), current mark proxy (when available), expiry, strike, underlying price, DTE, ITM/OTM (derived from spot vs strike).
- **Outputs (structured only, request-time only, never in decision_latest.json):** `pct_max_profit`, `dte`, `mark_proxy`, `assignment_risk` (bool + reason code/fields), `roll_window` (bool + fields), `recommended_action_code` (safe enum: CLOSE | ROLL | HOLD), `recommended_by` "r243".
- **Rules (conservative defaults):**
  - **PROFIT_TARGET_HIT:** if pct_max_profit >= threshold → recommended_action_code CLOSE.
  - **ROLL_WINDOW:** if dte <= N and position open → ROLL or CLOSE depending on risk.
  - **ASSIGNMENT_RISK:** if ITM and low extrinsic proxy and dte small → CLOSE or ROLL.
  - Same inputs → same outputs (deterministic).

### Part B — API + Slack + Dashboard

- Extend GET `/api/ui/action-needed` so options items for tracked positions include the new lifecycle fields (pct_max_profit, mark_proxy, assignment_risk, roll_window, recommended_action_code when from position lifecycle). No FAIL_/WARN_ in response.
- Slack actionable message: include symbol/strategy/exp/strike/dte/pct_max_profit and action; no raw codes.
- Dashboard Action Needed: show lifecycle details (safe text); keep severity ordering.

### Part C — wheel_state retention

- Add deterministic retention for `wheel_state.json` `linked_position_ids`: per-symbol cap (e.g. keep last N position IDs) to prevent unbounded growth.
- Document retention rule in CLEANUP_POLICY.md or appropriate doc.
- Tests to enforce retention behavior.

## Non-scope

- No new brokers or auto-execution.
- No persistence of lifecycle fields into decision store.
- No change to decision artifact schema.

## Test plan

- **Backend:** action-needed JSON contains no FAIL_/WARN_; lifecycle fields not in decision_latest.json; determinism test for lifecycle; wheel_state retention test.
- **Frontend:** UI renders lifecycle details and never FAIL_/WARN_.
