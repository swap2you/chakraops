# R26.2 — Trade Ticket v2 (Execution Plan + Journal Draft)

## Scope

New Trade Ticket **page** (v2) with execution plan and journal draft. Entry from Dashboard Action Needed and Symbol Diagnostics. Manual-only; no broker automation. Supports SHARES BUY/SELL, CSP OPEN/CLOSE, CC OPEN/CLOSE.

## Non-negotiables

- Decision artifacts code-only; no prose/FAIL_/WARN_ in decision_latest.json.
- UI safe labels only; no raw FAIL/WARN.
- Determinism: ticket output deterministic for same snapshot inputs.
- No broker automation; no new strategies beyond CSP/CC/SHARES.
- Gates + evidence in out/verification/R26.2/notes.md + UAT.

## 1) Trade Ticket page (v2)

- **Entry:** Dashboard Action Needed rows → "Ticket"; Symbol Diagnostics → "Trade Ticket" button.
- **Types:** SHARES BUY/SELL, CSP OPEN/CLOSE, CC OPEN/CLOSE.

## 2) Ticket contents (operator-ready)

- **Snapshot header:** symbol, strategy, cadence mode, as_of (ET); recommended action (Entry/Close/Roll/Hold) safe label.
- **Sizing:** recommended_qty or recommended_contracts, notional, constraints (safe labels), cash-secured available/committed (CSP), risk proxy move %, loss/contract, cap, enforced.
- **Contract details (options):** expiry, strike, right, DTE, mark (value/source/age), premium, max profit %.
- **Execution steps:** Copy/paste checklist (limit order, quantity, before-submit checks, after-fill steps).
- **Journal draft:** Pre-filled payload; "Save to Journal" (API); "Copy JSON", "Copy CSV line".

## 3) Backend

- **GET /api/ui/trade-ticket?symbol=...&strategy=...&action=...** — Returns ticket model: diagnostics snapshot fields, action-needed sizing, guardrails metrics, earnings advisory (advisory). No persistence to decision artifacts.
- **POST /api/ui/journal/from-ticket** — Accepts journal entry payload; writes via journal DB (same as POST /api/ui/journal); ticket-friendly schema.

## 4) Frontend

- **TradeTicketPage.tsx** at route /ticket?symbol=...&strategy=...&action=...
- Links: Dashboard Action Needed → "Ticket"; Symbol Diagnostics → "Trade Ticket".
- Compact UI: accordions (Snapshot / Sizing / Contract / Steps / Journal); copy buttons.

## 5) Tests

- Backend: test_r262_trade_ticket.py — ticket endpoint deterministic, no FAIL_/WARN_; journal-from-ticket writes (temp DB).
- Frontend: TradeTicketPage renders with mock; copy buttons; Save to journal mutation; no FAIL/WARN in DOM.
