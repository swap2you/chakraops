# R24.5.1 — Earnings Sanity + Scaling Fix (Patch)

**Scope:** Patch to R24.5. Eliminate bogus earnings outputs and fix implied move scaling.

## Requirements

1. **nextErn validation**
   - If missing, empty, `"0000-00-00"`, or invalid date ⇒ `earnings_data_status="Unavailable"` and set all earnings fields to null except `earnings_as_of`.

2. **earnings_days**
   - If `daysToNextErn` is a valid int ≥ 0, use it.
   - Else compute calendar days from snapshot as_of (America/New_York) to nextErn (only when nextErn is valid).

3. **impliedEarningsMove scaling**
   - If 0 < value ≤ 1.0 ⇒ interpret as fraction ⇒ `pct = value * 100`.
   - Else if 1.0 < value ≤ 50 ⇒ interpret as percent ⇒ `pct = value`.
   - Else ⇒ invalid ⇒ null (no 500%+ bogus values).

4. **Status OK**
   - Only when nextErn is valid **and** earnings_days is computed/valid.

5. **Frontend**
   - Hero pill only when `earnings_data_status=="OK"` and `earnings_days` is not null and next date is valid. Never show "Earnings: 00" or `0000-00-00`.
   - Risk flags: if status ≠ OK show "Unavailable"; do not show bogus date/move.

6. **Non-negotiables unchanged**
   - No prose in decision artifacts; no FAIL_/WARN_ persisted or in UI; deterministic snapshot semantics; gates pass.
