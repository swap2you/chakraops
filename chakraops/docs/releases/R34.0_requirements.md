# R34.0 Requirements — Canonical Live Cutover (closes R33 blocker / H-5)

**Branch:** `release/R31-R35-program` (program milestone 4)
**Risk level:** Level 3 — application refactor and analytical presentation.

## Objective

Close the Claude R33 BLOCKER by making the canonical decision engine the authoritative
producer of the primary live recommendation, with stale-data safety, recommendation-set
capital safety, and a deliberate persistence decision — before any broader product
consolidation.

## Consolidated R32–R34 blocker remediation (2026-06-22) — requirements & status

R-WR (Phase 1) — weekly universe refresh must be **operational**: compute deterministic
weekly universe → apply via the canonical store → append exactly one history record;
idempotent per ISO week; atomic (no partial apply); records reason/added/removed/timestamp/
source/outcome; safe manual/admin trigger; no auto-scheduling (R35 owns). **DONE.**

R-RED (Phase 2) — credentials must never appear in logs/stderr/exceptions/evidence: redact
token query params, bearer/api-key headers, credential URLs; preserve endpoint/status/
classification; regression tests with fake creds; never read/print the local `.env`. **DONE.**

R-FC (Phase 3) — the live route must be **fail-closed**: never claim canonical authority when
canonical computation fails; no legacy actionable fallback; explicit degraded/unavailable
contract with empty actionable + reason code (`CANONICAL_ENGINE_UNAVAILABLE`); consistent
decision-source semantics across action-needed, daily-overview, symbol-diagnostics. **DONE.**

R-CASH (Phase 4) — do not infer available cash from total equity; cash-consuming CSP/share-buy
must be non-actionable when cash is unknown; covered calls may proceed with sufficient shares;
flag sector concentration that cannot be evaluated rather than silently ignoring the limit;
preserve cash-buffer/allocation invariants. **DONE.**

R-STAGED (Phases 5–6) — rendered visual canonical cutover (Dashboard/Today/Symbol) and
required product correctness. **DONE (final cutover pass, 2026-06-22).** Dashboard/Today/Symbol
render the canonical block as primary (legacy demoted to collapsed diagnostics); shared-table
`<tr>` DOM fix; Backtest SIMULATION label; positions pagination; navigation grouping;
understandable loading/empty/stale/unavailable/failure states. **H-5 CLOSED** after the
rendered-UI cutover page tests passed. Post-R35 enhancements (drag-and-drop, broad redesign,
physical legacy-module deletion, bundle architecture, multi-user DB) remain out of R34 scope.

R-TXN (Phase 1, final) — weekly refresh must be **transaction-safe**: one cross-process lock
spanning idempotency→snapshot→overlay→history→completion; atomic writes (flush+fsync+`os.replace`);
journal-based deterministic recovery; rollback/recovery failure raises an explicit critical error;
concurrent same-week calls produce one applied refresh + one history record. **DONE.**

R-RED2 (Phase 2, final) — ORATS redaction must be **complete** across all application paths:
sanitize at exception construction; never bare-rethrow token-bearing exceptions (wrap with
sanitized messages, `from None`); redact bodies/snippets/headers/diagnostics/boot-probe/HTTP
errors; fake-secret regression tests; tracked-code + evidence secret scan. **DONE — 0 hits.**

R-SECT (Phase 3, final) — **live sector enforcement**: map symbol/sector exposure from portfolio
data; enforce profile sector caps; BLOCK incremental CSP/share-buy when sector data is unavailable;
allow + flag existing-share covered calls; deterministic reason codes. **DONE.**

## Functional requirements (delivered in this pass)

1. The canonical engine produces the **primary** live recommendation surfaced by
   `/api/ui/action-needed` (consumed by Dashboard + Today) and Symbol Diagnostics. (DONE)
2. The live API may use an adapter for backward compatibility, but the canonical engine
   produces the primary decision. (DONE — `legacy_adapter.py` + `live_service.py`)
3. The legacy evaluator/ranking stack must not independently produce a conflicting primary
   recommendation; legacy output is clearly labeled non-authoritative/diagnostic. (DONE)
4. The R32 `stale_data_gate` is enforced on every route capable of returning ACTIONABLE;
   missing/stale critical data yields BLOCKED/WATCH/STAY_IN_CASH, never ACTIONABLE. (DONE)
5. Invalid `profile_overrides` returns HTTP 422, not 500. (DONE)
6. Active profile is carried through the live response; top actionable limited to 5–7;
   manual-only label present. (DONE)
7. Recommendation-set capital safety: per-suggestion-not-additive label, total capital
   required, over-capital warning, profile cash buffer preserved, no assumed leverage. (DONE)
8. A deliberate persistence decision is documented before any DB change. (DONE — RETAIN)

## Non-functional requirements

- No order routing, no broker integration, no auto-trading, no silent data fallback.
- No secrets in logs/evidence; local ORATS `.env` untouched.
- Heavy calculations/jobs remain outside HTTP request handlers (live cutover reads the
  persisted artifact and runs the deterministic engine in-process over a small candidate set).
- R33 strategy mathematics unchanged.

## Acceptance criteria

- Tests prove: canonical authoritative live source, stale-data live-route blocking, no
  conflicting primary, profile carried, manual-only, top 5–7 cap, capital-set warning, 422.
- AGENTS.md baseline gates pass (backend pytest, frontend tests, frontend build).
- Persistence decision recorded before any schema change.

## Out of scope (deferred to post-R35 — not required for R34)

Drag-and-drop dashboard customization; broad visual redesign; physical deletion of all legacy
modules; extensive bundle/code-split architecture beyond low-risk improvements; advanced
multi-user database architecture. All R34-required outcomes (transaction-safe refresh, complete
ORATS redaction, live sector enforcement, rendered canonical cutover, Symbol canonical/empty-state,
table DOM fix, SIMULATION label, navigation grouping, positions pagination, gates) are DONE.
