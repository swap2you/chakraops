# Release R22.9 — Fix Pack (schema-compat + trade ticket identity + strict code-only + score breakdown UI)

**Date:** 2026-02  
**Goal:** (1) Eliminate decision artifact loader errors, (2) enforce strict code-only persisted artifacts (no prose, no diagnostics persisted), (3) fix Trade Ticket contract identity propagation, (4) add Score breakdown panel on Symbol page (request-time only).

---

## Scope

### Part 1 — Persisted artifact schema + hygiene (hard rule)

- **to_dict_persist()** outputs ONLY: `metadata`, `symbols[]`, `selected_candidates[]`, `candidates_by_symbol`, `gates_by_symbol`, `earnings_by_symbol`, `warnings`.
- **Explicitly DROPPED** from persisted JSON:
  - `diagnostics_by_symbol` (diagnostics is request-time only)
  - any `reason` strings (use `reason_code` only)
  - any `note` strings (use `status_code` for earnings)
  - `why_this_trade` on candidates
- **applied_caps** (in symbol `score_breakdown` / `score_caps`): persisted as `{type, cap_value, before, after, reason_code}` only; no `reason`. If `reason_code` missing, map to `REGIME_CAP`.
- All codes fields (`primary_reason_codes`, `rank_reason_codes`, `reason_code`, `status_code`) match `^[A-Z0-9_]+$`.

### Part 2 — Backward compatible loading (stop log spam)

- **GateEvaluation:** `reason` is optional (default `None`). Persisted gates have only `name` and `status`.
- **CandidateRow:** `why_this_trade` is optional (default `None`). Persisted candidates omit it.
- **from_dict:** Tolerates missing keys; fills defaults for optional fields when loading from minimal JSON. When `diagnostics_by_symbol` is absent, uses `{}`.

### Part 3 — Trade Ticket identity fix

- **contract_key** normalized format: `{strike}-{expiry}-PUT|CALL` with strike as integer (no trailing `.0`).
- **candidate_persist** always derives/includes `contract_key` and `option_symbol` for CSP/CC candidates.
- API responses (universe, symbol-diagnostics) already pass `selected_contract_key` and `option_symbol` from store; loader fix ensures artifact loaded from disk has these fields so Trade Ticket receives them.

### Part 4 — Score breakdown UI panel (request-time only)

- **Score breakdown** card on Symbol Execution Console (SymbolDiagnosticsPage): shows `data_quality_score`, `regime_score`, `options_liquidity_score`, `strategy_fit_score`, `capital_efficiency_score`, `composite_score`, `raw_score`, `final_score`.
- **Applied caps** shown as code-only labels (`reason_code`) + before/after/cap_value.
- Data comes from diagnostics response (request-time); **not** persisted in `decision_latest.json`. When diagnostics empty (e.g. after load from disk), `score_breakdown` is taken from symbol summary when present.

## Tests

- **Hygiene:** `test_r229_persist_no_diagnostics_by_symbol`, `test_r229_persist_no_reason_keys`, `test_r229_loader_regression_minimal_persisted_json`; `test_artifact_written_by_store_passes_hygiene` asserts no `diagnostics_by_symbol` and no `reason` keys in on-disk artifact.
- **Loader:** Load minimal JSON (no `diagnostics_by_symbol`, gates without `reason`, candidates without `why_this_trade`) → no exception; `contract_key` / `option_symbol` present on loaded candidates.
