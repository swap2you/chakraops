# R24.5 — Earnings Advisory (Hero Pill + Risk Flags) Using ORATS

**Superseded by R24.5.1.**

**Date:** 2026-02

## What changed

- **ORATS earnings fetch:** `/datav2/cores` with fields `ticker`, `nextErn`, `daysToNextErn`, `impliedEarningsMove` (and optional `ieeEarnEffect`). Optional `/datav2/hist/earnings` to derive AMC/BMO for next earnings date.
- **Request-time earnings fields** (symbol diagnostics; not in decision artifact): `earnings_next_date`, `earnings_days`, `earnings_annc_tod`, `implied_earnings_move_pct`, `earnings_data_status` (OK/Unavailable/Stale), `earnings_as_of`. Days computed from as_of in America/New_York.
- **Snapshot semantics:** Earnings data stored in eval snapshot so per-symbol recompute matches; no earnings fields in decision_latest.json.
- **API:** Earnings payload includes new fields; "Not evaluated" replaced with "Unavailable" when status not OK. No FAIL_/WARN_ in responses.
- **Frontend:** Hero pill (orange) when earnings OK and next date present: "Earnings: Today" / "Earnings: Nd" / "Earnings: Mmm D"; "(AMC)"/(BMO)" when known. Risk Flags show next date, days, implied move %; "Unavailable" when not OK; "Advisory only" note.
- **No hard blocker:** Earnings are advisory only; eligibility is not blocked or failed due to earnings.
