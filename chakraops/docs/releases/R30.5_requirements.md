# R30.5 — Journal Readiness Pack Ops: filter + bulk export (JSONL) (NO GIT)

**NO GIT.** Manual-only. No broker automation. No schedulers.

## Non-negotiables

- Manual-only. No broker automation. No schedulers.
- Do NOT write out/decision_latest.json.
- UI must never display raw FAIL/WARN/PASS or FAIL_/WARN_ substrings.
- Export must contain no forbidden tokens and no secrets (sanitizeForExport + safeForReadinessDisplay rules).
- Determinism: stable ordering (by journal entry timestamp then id).

## Goal

1) Journal page can filter "Has readiness pack".  
2) Provide a manual "Download readiness packs (JSONL)" bulk export for the currently filtered journal list (bounded, deterministic).

## Scope

### Backend

- **GET /api/ui/journal/readiness-packs/export** — Query: has_pack (default true), start_utc (optional), end_utc (optional), limit (default 200, max 1000). Select journal entries matching range/order deterministically (created_ts ASC, id ASC). For each entry with READINESS_PACK attachment: load attachment JSON, re-sanitize with sanitize_json_for_export; build safe journal_entry subset (id, symbol, created_at_utc, mode, strategy). Return application/jsonl with Content-Disposition attachment; filename readiness_packs_<utc_ts>.jsonl. No state writes.
- **Tests:** test_r305_journal_readiness_packs_export.py — export returns JSONL and is deterministic; lines have no forbidden tokens; does not write decision_latest; limit applied and ordering stable.

### Frontend

- **JournalPage:** Filter toggle "Has readiness pack" (default On); data-testid journal-filter-has-pack. Button "Download readiness packs (JSONL)"; data-testid journal-download-readiness-packs. Uses current filters (date range + has_pack + limit); calls apiGetBlob and triggers download.
- **Tests:** Toggle changes filtered list; download button calls mocked download with correct params; document has no forbidden tokens.
