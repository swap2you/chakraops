# R26.7 — Restore drill + smoke test

## Summary

Prove backups are usable: restore_drill.sh restores latest out/data backups to a temp dir, runs the backend with OUT_DIR/DATA_DIR, and hits healthz, system-health, and reports endpoints. Backend supports OUT_DIR and DATA_DIR env overrides (minimal, for drill and ops).

## Changes

- **scripts/restore_drill.sh** — Finds latest out_*.tar.gz and data_*.tar.gz in ./backups; extracts to temp; exports OUT_DIR, DATA_DIR; starts uvicorn on port 8010; retries until healthz OK; calls healthz, system-health, reports/monthly, reports/monthly/close; prints DRILL OK and temp paths; cleans up unless --keep.
- **Backend** — evaluation_store_v2: at import, if OUT_DIR is set, set_output_dir(Path(OUT_DIR)). Journal, checklist, monthly_close, universe_admin: if DATA_DIR is set, use it for DB/reports paths (else unchanged repo-relative paths).
- **Docs** — R26.7 requirements, release notes, RELEASE_CHECKLIST section, README "Quarterly restore drill".

## Behavior

- Drill uses port 8010 to avoid conflict with a running app. UI routes may return 401 without x-ui-key; healthz and smoke calls prove the process and restored state are usable.
- POST monthly/close creates pack under temp data/reports when DATA_DIR is set.

## How to test

1. Create backups: ./scripts/backup_out.sh && ./scripts/backup_data.sh
2. Run drill: ./scripts/restore_drill.sh
3. Expect "DRILL OK" and backend to stop; temp removed.
4. Optional: ./scripts/restore_drill.sh --keep to inspect temp and leave backend running.
