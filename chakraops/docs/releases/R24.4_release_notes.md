# R24.4 — Mark Proxy Provenance/Freshness + Roll Rationale (Operator Trust)

**Date:** 2026-02

## What changed

- **Mark proxy provenance and freshness (request-time only):** Position lifecycle (R24.3 extended) now outputs `mark_value`, `mark_source` (MID | LAST | BIDASK_MID | BID | ASK | UNKNOWN), `quote_ts` (ISO when available), and `mark_age_sec` (when quote_ts and as_of time available). Deterministic selection order: MID → LAST → BIDASK_MID → BID → ASK → UNKNOWN. None of these fields are persisted to decision artifacts.

- **Roll rationale (structured, safe):** When `recommended_action_code == ROLL`, lifecycle adds `roll_window_threshold_dte` (e.g. 14) and `roll_reason_codes` (e.g. `["DTE_WINDOW"]`). Safe enums only; no prose in decision store.

- **API:** GET `/api/ui/action-needed` options items include mark provenance/freshness and roll rationale when present. No FAIL_/WARN_ in response.

- **Slack:** Actionable message includes mark provenance/freshness and max profit % when present (e.g. "Mark: 1.23 (MID, 18s old) | Max profit: 52% | Recommend: CLOSE"). No raw codes.

- **Dashboard:** Action Needed cards show Mark value + source + age, Max profit %, Recommend (safe label), and for ROLL "Reason: DTE window" (safe mapping from roll_reason_codes). No raw codes in UI.

## Endpoints

- **GET /api/ui/action-needed** — Options items may include `mark_value`, `mark_source`, `quote_ts`, `mark_age_sec`, `roll_window_threshold_dte`, `roll_reason_codes` (when from position lifecycle). Backward compatible.
