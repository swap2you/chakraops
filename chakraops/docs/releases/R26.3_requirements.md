# R26.3 — Daily Operator Workflow lock-in ("Today" command center)

## Scope

Single **Today** page that consolidates run/refresh, Action Needed, Trade Ticket queue, Journal checkpoint, and Notifications inbox. Manual-only; no broker automation.

## Non-negotiables

- Decision artifacts code-only; no prose/UI strings; no raw FAIL_/WARN_ in decision_latest.json.
- UI safe labels only; no raw FAIL/WARN.
- Determinism: Today view uses a consistent snapshot timestamp (as_of) across sections where possible.
- No broker automation.
- Gates + evidence in out/verification/R26.3/notes.md + UAT checklist.

## 1) TodayPage (single workflow)

Sections top to bottom, minimal scrolling:

- **A) Run / Refresh** — Button to run evaluation (existing eval endpoint); last run status (as_of ET, cadence mode); quick health: ORATS status, Earnings probe status, Guardrails status.
- **B) Action Needed** — From /api/ui/action-needed; compact rows: symbol, strategy, recommended action, size/notional, key constraints, deep link to Trade Ticket; for CLOSE/ROLL show lifecycle reason and mark/profit/DTE when available; safe labels only.
- **C) Trade Ticket queue** — Local queue in localStorage; when user clicks "Ticket" on a row, add to queue; each item: symbol, strategy, action, created_ts; buttons: Open Ticket, Remove, Mark Done (Done = remove + prompt to save journal if not saved).
- **D) Journal checkpoint** — Journal entries for today (or selected date); "Add manual entry" (existing Journal add modal or deep link); "Missing journal" reminder if a ticket was marked done but no journal entry for that symbol+today.
- **E) Notifications inbox** — NEW notifications; inline actions: Ack, Archive; bulk: Ack all NEW, Archive all ACKED (R25.4); encourage "clear inbox daily".

## 2) Backend (minimal)

- **GET /api/ui/today/summary** — Single payload: latest_run_ts / as_of, cadence { mode, eligibility_as_of }, guardrails health, notifications health, earnings probe (e.g. SPY summary), counts: action_needed_count, notifications_new_count. No heavy ORATS calls if avoidable.

## 3) Frontend

- Route /today; navigation entry "Today" (optional default landing).
- TodayPage uses existing hooks + useTodaySummary; localStorage for ticket queue (no backend persistence v1); safe label mapping everywhere.

## 4) Tests

- Backend: test_r263_today_summary.py — schema and no FAIL_/WARN_ in JSON.
- Frontend: TodayPage renders all sections with mocked hooks; queue add/remove (localStorage); notifications actions call mocked mutations; no FAIL/WARN in document.textContent.
