# R25.0 — Ops hardening for deployed ChakraOps (restart policy, healthz, logs, backup)

## Scope

Improve operational reliability and observability for deployed instances: lightweight healthz endpoint, Docker restart policy and log limits, and a backup script for out/. No secrets; decision artifact semantics and same-origin /api unchanged.

## Requirements

1. **Healthz**
   - GET /api/healthz returns 200 with `{status: "ok", ts: <iso>}` (and optionally `ok: true` for compatibility). Must not call ORATS or load heavy state.
   - Backend test for GET /api/healthz (status 200, body shape).

2. **Compose prod hardening**
   - In docker-compose.yml and docker-compose.prod.yml (where applicable): `restart: unless-stopped` for backend, frontend, and caddy (prod).
   - Logging: json-file driver with max-size and max-file.
   - ./out bind mount remains on backend service.

3. **Backup script**
   - Add scripts/backup_out.sh: archive ./out into ./backups/out_<timestamp>.zip (or .tar.gz); retain last BACKUP_KEEP_N (default 14); delete older archives.
   - Document in chakraops/README.md: how to run backup, restore steps.

4. **Gates and verification**
   - pytest, frontend test, frontend build pass; outputs in out/verification/R25.0/notes.md.
   - UAT: prod compose up; auth works; /api/healthz 200 via proxy; stop backend then restart and confirm recovery; run backup script and verify archive + retention.

## Non-negotiables

- No secrets committed. Decision artifact semantics unchanged. Same-origin /api model (R24.9) unchanged. Gates pass and evidence in out/verification/R25.0/notes.md.
