# R26.4 Release Notes — EOD routine + weekly review automation

## Summary

- **Checklist persistence:** SQLite checklist_state (EOD by date, Weekly by YYYY-WW); get/set/list via app/core/ops/checklist_store_r264.py.
- **API:** GET /api/ui/ops/checklist, POST /api/ui/ops/checklist/mark-done, GET /api/ui/ops/eod-summary, GET /api/ui/ops/weekly-summary.
- **Frontend:** TodayPage EOD Checklist section (counts, Mark EOD Done); WeeklyReviewPage (weekly-summary, Mark Weekly Done); pending banners.
- **Reminders:** At 19:00 ET emit OPS_EOD_CHECKLIST_REMINDER if EOD not done; Sunday 19:00 ET emit OPS_WEEKLY_REVIEW_REMINDER if weekly not done; dedupe per key.

## Backend

- checklist_store_r264: init_checklist_db, checklist_get, checklist_set_done, checklist_list.
- Ops routes under /api/ui/ops/; eod-summary and weekly-summary aggregate from store + journal.
- Reminder emission from nightly scheduler (19:00 ET); dedupe via notification type + details.key.

## Frontend

- TodayPage: EOD section with eod-summary counts and Mark EOD Done; banner when EOD pending.
- WeeklyReviewPage at /weekly; weekly-summary + checklist; Mark Weekly Done; banner when weekly pending.

## Tests

- test_r264_ops_checklists.py; TodayPage EOD + WeeklyReviewPage tests; no FAIL/WARN in DOM.
