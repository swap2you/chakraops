# R30.6 — Orchestration Baseline + Documentation Governance

## Title

R30.6 — Orchestration baseline + documentation governance

## Goal

Establish a durable cross-tool governance baseline for the ChakraOps repository. Create authoritative agent-contract files, documentation source-of-truth references, known-issue registry, release handoff template, and Cursor/Claude rules. Ensure all active agents operate from a consistent, documented contract before the next implementation release begins.

## Scope

Documentation and governance files only:

- `.gitattributes` — line-ending normalization
- `AGENTS.md` — cross-tool agent contract
- `CLAUDE.md` — Claude-specific quick reference
- `.cursor/rules/chakraops.mdc` — Cursor implementation rules
- `docs/master/SOURCE_OF_TRUTH.md` — authoritative path registry
- `docs/master/CURRENT_STATE.md` — current repo snapshot
- `docs/master/KNOWN_ISSUES.md` — known-issue register
- `docs/master/RELEASE_HANDOFF_TEMPLATE.md` — reusable handoff template
- `chakraops/docs/releases/R30.6_requirements.md` (this file)
- `chakraops/docs/releases/R30.6_release_notes.md`
- `chakraops/docs/releases/RELEASE_CHECKLIST.md` — R30.6 section added

## Non-Goals

- No trading logic changes
- No frontend code changes
- No backend code changes
- No ORATS logic changes
- No database changes
- No scheduler changes
- No GitHub Actions changes
- No runtime files under `out/` or `data/`
- No deletion or movement of existing documentation
- No test additions or modifications

## Acceptance Criteria

1. All files listed in scope exist with correct content.
2. `AGENTS.md` defines authority, tool roles, release workflow, trading safety, artifact safety, required gates, and forbidden actions.
3. `CLAUDE.md` references `AGENTS.md` and provides correct paths and commands.
4. `.cursor/rules/chakraops.mdc` enforces scope, Git, protected-path, and STEP-report rules.
5. `docs/master/SOURCE_OF_TRUTH.md` defines the conflict resolution order.
6. `docs/master/CURRENT_STATE.md` accurately reflects R30.5 as the latest merged release.
7. `docs/master/KNOWN_ISSUES.md` registers all ten known issues with impact and handling.
8. `docs/master/RELEASE_HANDOFF_TEMPLATE.md` contains all required fields.
9. `RELEASE_CHECKLIST.md` contains a correctly placed unchecked R30.6 section.
10. No code, tests, UI, or runtime files were modified.

## Verification Steps

1. Confirm all files exist at their specified paths.
2. Confirm `git status --short` shows only the expected new/modified files (no unintended changes).
3. Run regression gates after operator review:
   - `cd chakraops && python -m pytest tests -q --tb=short`
   - `cd frontend && npm run test -- --run`
   - `cd frontend && npm run build`
4. Record gate results in `out/verification/R30.6/notes.md`.
5. Manual UAT: verify agent files are readable and source-of-truth paths are correct.
