# R25.4 — Phase 4 Notifications Overhaul (Release Notes)

## Summary

Stateful notifications inbox: NEW → ACKED → ARCHIVED with bulk ack/archive, transition-aware dedupe (no duplicate while active), actionable payload parity, and Notifications Health in System Diagnostics. UI and API use safe labels only; no FAIL/WARN in artifacts or display.

## Changes

### Backend

- **Query:** GET /api/ui/notifications supports `state`, `symbol`, `type`, `limit`, `offset`. Response includes `created_ts` (timestamp_utc), `acked_ts`, `archived_ts`, `updated_ts` where applicable.
- **Bulk:** POST /api/ui/notifications/ack-bulk (ack all NEW, optional filter); POST /api/ui/notifications/archive-bulk (archive all ACKED, optional filter).
- **Dedupe:** Options lifecycle and shares exit use transition-aware dedupe: do not create a new notification if an **active** (NEW or ACKED) one exists for the same (entity_key, event_type). After ARCHIVED/DELETED, re-trigger may create again.
- **System Health:** Notifications block with last_emitted_ts, count NEW, count ACKED, count ARCHIVED (safe labels only).

### Frontend

- Notifications page: tabs NEW / ACKED / ARCHIVED / ALL; search by symbol and type; “Ack all NEW” and “Archive all ACKED” (or archive all); per-row Ack/Archive unchanged.
- Notification cards: title and key fields (options: symbol, contract, profit %, DTE; shares: symbol, hit_type, target/stop); deep link to Symbol Diagnostics with tab (options/shares).
- No FAIL/WARN in UI; safe labels only.
- System Diagnostics: Notifications Health section (counts, last emitted).

### Behavior

- **Determinism:** Same inputs → same dedupe result; no time-window-only spam suppression for actionable types.
- **Decision artifacts:** Unchanged; no prose or FAIL_/WARN_ persisted.

## How to test

1. Create a test notification (shares exit or options lifecycle) and confirm it appears in NEW.
2. Ack it → moves to ACKED.
3. Archive it → moves to ARCHIVED.
4. Use “Ack all NEW” and “Archive all ACKED”; confirm counts update.
5. Run eval twice with same trigger; confirm dedupe (no second notification until first is archived).
6. Grep decision_latest.json for FAIL_|WARN_ → 0 matches.
7. System Diagnostics → Notifications Health shows counts and last emitted.
