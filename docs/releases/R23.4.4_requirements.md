# R23.4.4 — Symbol Diagnostics Options Fix Pack

## Objectives

- Restore Options tab on Symbol Diagnostics (Execution Console) so previously populated fields (price, technicals, targets, exit plan, candidate table) show real values instead of dashes when loading from store.
- No new persistence in decision artifacts; all rebuild is request-time only in `/api/ui/symbol-diagnostics` and UI.

## Scope

### Backend (request-time only)

- When diagnostics_details is missing (store load): rebuild technicals via eligibility engine (`_build_technicals_at_request_time`); rebuild exit_plan from technicals via `build_exit_plan`; populate regime, explanation (stock_regime_reason, support_condition, resistance_condition), rejected_count from summary when applicable.
- Stock price fallback from summary (already present); technicals from candles/eligibility when possible.
- Targets, hold_time_estimate, exit_plan present when strategy is CSP/CC and inputs allow.
- Candidate table: symbol-level explanation (regime, support, resistance) so columns are not blank.

### Frontend

- Options tab: no Shares plan content; collapsible Details (As-of/Inputs, debug raw reason).
- Score breakdown: show "Capped by" line when score_caps.applied_caps present (before → after).
- Technical details, Targets & hold-time, Exit plan rendered with values when API provides them.

### Constraints

- Do not add new persistence to decision_latest.json. No FAIL_/WARN_ in UI. No Copilot changes.

## Acceptance

- NVDA/SPY Options page shows RSI, ATR, regime, support/resistance, targets, hold-time, exit plan when data is available.
- Candidate table has regime/support/liquidity/iv from symbol-level explanation (no permanently blank columns when backend sends explanation).
- Gates pass; verification recorded in out/verification/R23.4.4/notes.md.
