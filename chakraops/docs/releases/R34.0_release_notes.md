# R34.0 Release Notes — Canonical Live Cutover (closes R33 blocker / H-5)

**Branch:** `release/R31-R35-program` (program milestone 4)
**Status:** Cutover core (Phases 0–3) delivered + gate-verified. Broader product phases (4–9) STAGED.

## Summary

R34.0 closes the Claude R33 **BLOCKED** verdict by making the canonical R33 decision
engine the **authoritative producer of the primary live recommendation** at the API/data
layer. The legacy evaluator/ranking stack no longer defines the primary action: it is
relabeled non-authoritative/diagnostic. The R32 stale-data gate is enforced on the live
actionable path, recommendation-set capital safety is surfaced, and the mandatory
persistence decision is documented (RETAIN current stack, no migration).

This is an **advisory, manual-only** system. Nothing routes orders; there is no broker
integration, no auto-trading, and no silent data fallback.

## Delivered

- **Canonical live cutover (H-5, API/data layer):**
  - `app/core/decision_engine/legacy_adapter.py` maps canonical `DecisionOutput` → live UI
    shapes (no `FAIL_`/`WARN_` leakage; `recommended_by = canonical_decision_engine`).
  - `app/core/decision_engine/live_service.py` builds canonical `DecisionInput`s from the
    already-persisted v2 decision artifact, runs the deterministic engine **in-process at
    request time** (no ORATS calls, no fallback), and returns one authoritative block.
  - `/api/ui/action-needed` now returns `authoritative_recommendations` (canonical),
    `capital_safety`, `decision_source`, and `active_profile`; legacy `options`/`shares`
    lists are kept as `legacy_lists_role = diagnostic_non_authoritative`.
  - Symbol Diagnostics returns a `canonical_decision` block + `decision_source`; Today
    summary advertises `decision_source` and the canonical action-needed source.
- **Stale-data safety:** the R32 `stale_data_gate` is wired through the canonical engine on
  the live actionable path. Missing/stale critical data yields BLOCKED/WATCH/STAY_IN_CASH —
  never ACTIONABLE.
- **No conflicting primary:** the response declares a single authoritative `decision_source`;
  legacy is non-authoritative.
- **Recommendation-set capital safety:** `per_suggestion_not_additive` label, total capital
  required for the displayed set, deployable capital after the profile cash buffer, and an
  over-capital warning. No assumed leverage/margin. R33 sizing math unchanged.
- **API hardening:** invalid `profile`/`profile_overrides` → HTTP 422 (not 500).
- **Frontend:** authoritative types (`AuthoritativeRecommendations`, `CapitalSetSafety`,
  `CanonicalLiveItem`) and `useActionNeeded(profile?)` carrying the active profile.
- **Persistence decision:** RETAIN SQLite + append-only JSONL; no migration (see
  `docs/ai/releases/R34.0/persistence_decision.md`).

## Liquidity provenance

The artifact does not persist per-contract OI/volume/spread. Where the upstream batch
Stage-2 gate set `option_liquidity_ok == True`, the live service treats the contract as
liquidity-validated upstream and tags items with `LIQUIDITY_VALIDATED_UPSTREAM` (visible in
`reason_codes`); otherwise the canonical liquidity gate blocks. R33 math unchanged.
