# Release R29.6 — Integrity sample items: safe deep links

**Date:** 2026-02  
**NO GIT.** Manual-only.

**Goal:** Make integrity sample items actionable with safe deep links so the operator can go from a sample item to Positions (and optionally Diagnostics) without manual copying. Deterministic ordering preserved; no decision writes; no forbidden tokens.

---

## User-visible changes

- **Positions page — Integrity sample items:** Each sample item in "View details" now shows **"Open positions"** (link to /positions with symbol and include_paper) and **"Open diagnostics"** (link to /system) when the API provides them. Links use safe prebuilt URLs only.
- **System Diagnostics — Integrity Check card:** Same per-item "Open positions" and "Open diagnostics" links in the sample items list when expanded.

## API / backend

- **Sample item fields (R29.6):** Each item in sample_items (and last_sample_items in system-health) now includes:
  - `link_positions_url`: `/positions?source=db&symbol=<urlencoded_symbol>&include_paper=<true|false>`
  - `link_diagnostics_url`: `/system`
- State file and GET integrity-check / system-health responses include these fields. No new endpoints. No writes to out/decision_latest.json.

## Tests and evidence

- Backend: test_r296_integrity_sample_links.py — links present and deterministic; safe tokens only; no decision_latest write; state and health include links.
- Frontend: PositionsPage and SystemDiagnosticsPage — "Open positions" / "Open diagnostics" link href assertions; no forbidden tokens in document.
- Evidence: **out/verification/R29.6/notes.md**.
