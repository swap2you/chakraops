# R25.7 — Earnings Advisory Correctness + Consistency (Stabilization)

**Date:** 2026-02

## Summary

Stabilization release ensuring earnings advisory is evaluated consistently for every symbol, decision artifact uses only safe status codes (OK/Unavailable/Stale), implied move scaling is applied once, and UI never shows "Earnings: 00" or "0000-00-00".

## What changed

### Backend

- **Eval run:** Universe evaluation now fetches earnings advisory once per run (`fetch_earnings_advisory_batch`) and populates `earnings_by_symbol` with status from ORATS (OK/Unavailable/Stale). No symbol is left as "Not evaluated"; missing/error → Unavailable.
- **Persist:** `earnings_persist` never writes `EARNINGS_NOT_EVALUATED`; any such case is persisted as **Unavailable**.
- **Recompute:** Per-symbol recompute reuses snapshot earnings from `eval_snapshot.json` when not force-refreshing; otherwise fetches advisory for that symbol and uses same status set.
- **Implied move:** Scaling remains in `app.core.orats.earnings` only (0 < v ≤ 1 ⇒ pct = v×100; 1 < v ≤ 50 ⇒ pct = v; else null). No double application.

### Frontend

- Hero earnings pill only when `earnings_data_status === "OK"` and valid `earnings_next_date` + `earnings_days` (no "00", no "0000-00-00").
- Risk flags show "Unavailable" when status not OK.
- Implied move: show percent only when non-null; prefer null over misleading zero.

### Tests

- Backend: assert no `EARNINGS_NOT_EVALUATED` in persisted artifact after eval; determinism for earnings across recompute.
- Frontend: assert no bad strings ("0000-00-00", "Earnings: 00"); implied move formatting.
