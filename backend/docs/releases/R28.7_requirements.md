# R28.7 — Unified Positions Rebuild v1 (manual) + Diagnostics UI action

**NO GIT.** Manual-only. No broker auto-execution.

## Goal

Provide an explicit operator-controlled rebuild mechanism for the unified positions DB to remediate drift, with safe labels, determinism, and zero decision-artifact impact.

## Non-negotiables

- Manual-only (Robinhood). No broker auto-execution.
- Decision JSON artifacts are code-only. Canonical: out/decision_latest.json + history. Never persist prose/UI strings in decision artifacts.
- Never persist raw FAIL_/WARN_ tokens anywhere in decision artifacts.
- UI must never display raw FAIL/WARN/PASS words/codes. Safe labels only (e.g., OK / Review / Degraded / Blocked).
- Rebuild output ordering must be deterministic; stable IDs; no nondeterministic iteration.
- Repo hygiene: never stage/commit out/* runtime artifacts. out/verification/* is local evidence only.

## Scope

### A) Backend — Rebuild function + API endpoint

- **positions_unified_store_r279.py**
  - `rebuild_positions_unified(include_paper: bool = True) -> dict`: Single-process lock; wipe and recreate positions_open/positions_closed from same authoritative sources as unified aggregation (live shares, tracked live options, paper if include_paper). Deterministic insert order. Return only safe fields: status, status_label, rebuilt_open, rebuilt_closed, include_paper, started_at_utc, finished_at_utc. No notifications; no decision artifact writes.
  - Persist rebuild metadata to out/positions_unified_rebuild_state.json: status, status_label, timestamps, counts only. No FAIL/WARN/PASS.

- **ui_routes.py**
  - POST /api/ui/positions/unified/rebuild (query include_paper, default true). Response { ok, result }. If rebuild already running: ok=false, status Review, status_label "Rebuild already running". Never emit FAIL/WARN/PASS in response.
  - System-health block positions_unified_rebuild: status, status_label, last_rebuild_at_utc, last_rebuild_open_count, last_rebuild_closed_count, last_include_paper.

### B) Frontend — Diagnostics UI action

- Types: UiPositionsUnifiedRebuild in system-health; rebuild endpoint request/response types.
- api/queries.ts: usePositionsUnifiedRebuild() mutation; invalidate system-health and unified positions list on success.
- SystemDiagnosticsPage: "Unified Positions Rebuild" card (status, last rebuild timestamp, counts); "Rebuild unified positions" button with confirm dialog; button enabled when not running. No FAIL/WARN/PASS in UI.
- SystemDiagnosticsPage.test.tsx: Mock rebuild block; assert card and button; assert click triggers mutation with include_paper true; assert document has no /\b(FAIL|WARN|PASS)\b/.
