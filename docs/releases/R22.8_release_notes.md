# Release R22.8 — Offline Proof Harness (after-hours) + Golden Verification

**Date:** 2026-02  
**Goal:** Verify decision artifact hygiene, determinism snapshot behavior, and MTF semantics **without** live market hours or ORATS contract availability.

---

## Scope

- **Offline proof script:** `chakraops/scripts/offline_eval_proof.py` reads a fixture JSON, runs the same evaluation pipeline as `/api/ui/eval/run` (with fixture-driven staged results), writes artifacts via the **same store** (`out/decision_latest.json`, `out/eval_snapshot.json`), then runs hygiene checks and prints a per-symbol summary.
- **Fixture provider:** `app/core/eval/offline_fixture_provider.py` loads fixture and builds `UniverseEvaluationResult` (code-only friendly: `reason_code`, `rank_reason_codes`). Used by the script and by tests.
- **Golden fixture:** `tests/fixtures/r22_8_offline_proof_fixture.json` — symbols NVDA, NKE, HD with quotes and `eval_overrides` (verdict, score, primary_reason, stage_reached). No network; deterministic.
- **Tests:** `tests/test_offline_proof_harness_r228.py` — run offline proof, load produced `decision_latest.json`, assert hygiene (no prose, no spaces in strings, no FAIL_/WARN_, applied_caps have `reason_code`), primary_reason_codes strict regex, **golden determinism** (run twice → same score/band/verdict), and eval_snapshot written.

---

## Non-negotiables (unchanged)

- Decision JSON artifacts remain code-only (no prose, no UI strings, no FAIL_/WARN_ in values).
- Release gate: pytest, frontend tests, frontend build must pass.
- Repo hygiene: fixtures under `tests/fixtures`; `out/` only whitelisted artifacts.

---

## How offline proof works

1. **Load fixture** — JSON with `symbols`, `quotes`, optional `candles`/`chains`, and `eval_overrides` (verdict, score, primary_reason, stage_reached per symbol).
2. **Build mock result** — `build_universe_result_from_fixture(fixture_path)` returns `UniverseEvaluationResult` with `SymbolEvaluationResult` per symbol (code-only fields: `reason_code`, `rank_reason_codes`).
3. **Run same pipeline** — `evaluate_universe(symbols)` with `run_universe_evaluation_staged` patched to return the mock result. The real `evaluation_service_v2` builds `DecisionArtifactV2` and calls `store.set_latest(artifact)`.
4. **Same store writer** — `EvaluationStoreV2.set_latest` writes `decision_latest.json` via `to_dict_persist()` and `eval_snapshot.json`. No separate code path.
5. **Hygiene check** — Script (and tests) load the written JSON and assert: no forbidden prose substrings, no FAIL_/WARN_ patterns, no string values with spaces (zero-whitelist), applied_caps have `reason_code` not `reason`.

---

## How it guarantees artifact hygiene after-hours

- The **same** `to_dict_persist()` and store write path used in production is exercised. No live ORATS or market data required.
- After the script runs, `out/decision_latest.json` is produced by the real store; the script then validates it with the same rules as `test_decision_artifact_hygiene_r227.py` (forbidden keys, forbidden strings, applied_caps reason_code).
- Golden determinism test runs the offline proof **twice** and asserts score/band/verdict/primary_reason_codes identical — so any regression that introduces non-determinism or prose will fail the test.

## Commands

**Run offline proof (from repo root):**
```bash
python chakraops/scripts/offline_eval_proof.py --fixture chakraops/tests/fixtures/r22_8_offline_proof_fixture.json
```

**From chakraops directory:**
```bash
python scripts/offline_eval_proof.py --fixture tests/fixtures/r22_8_offline_proof_fixture.json
```

**Grep proof (no prose in decision artifact):**
```bash
grep -E "caps score|Not evaluated|Exit plan not computed|High data completeness|FAIL_|WARN_" out/decision_latest.json
```
(Should return nothing after a run with the current code path.)
