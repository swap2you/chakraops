# R24.1 — Actionable Trading Workflow v1

**Scope:** Notifications + position-aware actions + dashboard polish. No new write capabilities; decision JSON remains code-only.

## Part 1 — Position-aware next_action

- **next_action_code** (ENTRY | HOLD | CLOSE | ROLL | NONE) for OPTIONS and SHARES using existing data. CLOSE when target/stop hit; ROLL when low DTE (e.g. ≤14); ENTRY when eligible and no position.
- **next_action_details** (request-time only, not persisted) in GET /api/ui/symbol-diagnostics: `action`, `rationale_lines` (safe, plain-English), `key_numbers` (spot, t1, delta_best, dte, premium_est, etc.).
- Implemented in `app.core.next_action_r241`; wired in `_build_symbol_diagnostics_from_v2_store`.

## Part 2 — Actionable Slack message upgrade

- **build_actionable_message_r241** in `slack_dispatcher.py`: per-symbol Action block with next action, sizing, key levels; OPTIONS: contract_key/option_symbol, delta_best, dte, bid/ask/spread_pct; SHARES: spot, entry zone, stop, T1, suggested shares/cost, risk %. All copy safe/plain-English; no FAIL_/WARN_ or internal paths.
- **Sanitization:** FORBIDDEN_IN_SLACK (FAIL_, WARN_, api_key, token, traceback, File "); all rationale and text sanitized.
- **Dedupe:** same (symbol, strategy, action, contract/size) within N minutes (SLACK_ACTIONABLE_DEDUPE_MINUTES, default 15) unless severity changes; state in `chakraops/data/slack_actionable_dedupe.json`.
- **Tests:** `test_r241_slack_actionable_messages.py` — required fields, forbidden substrings, sanitize, dedupe key, dedupe suppress/allow.

## Part 3 — Dashboard workflow polish

- **GET /api/ui/action-needed:** Top 5 options + top 5 shares; each item: symbol, strategy, next_action_code, rationale_lines (1–2), key_number, tab, accordion_id (e.g. trade, trade-plan). **recently_changed:** stub (in-memory; does not error).
- **Dashboard Action Needed card** calls GET /api/ui/action-needed via useActionNeeded(); renders Options (5) + Shares (5); each row: symbol, action badge, one rationale line, key number; link to `/symbol-diagnostics?symbol=...&tab=...&accordion=...`.
- **SymbolDiagnosticsPage** reads `accordion` from URL and opens the corresponding accordion (initialAccordionId).

## Part 4 — Retention / out/ hygiene

- **DECISION_ARCHIVE_MAX / DECISION_HISTORY_KEEP:** Keep `decision_latest.json` plus the last K per-symbol decision history files (default K=50). Env: `DECISION_ARCHIVE_MAX` overrides `DECISION_HISTORY_KEEP`; both default to 50.
- **Where implemented:** `app.core.eval.evaluation_store_v2` — `_apply_retention(symbol)` runs after each symbol write; `prune_decision_archives()` prunes all symbol dirs under the decision store. See `DECISION_HISTORY_KEEP` and `prune_decision_archives` in that module.
- **How to verify:** Run `python -m pytest tests/test_decision_history.py -v --tb=short`; or set `DECISION_HISTORY_KEEP=3` and run eval, then inspect `out/decisions/<symbol>/` to confirm only last 3 runs kept.

## Tests

- **Backend:** test_r241_next_action.py — options/shares next_action_code transitions; build_next_action_details (no raw codes). test_r241_slack_actionable_messages.py — required fields, forbidden substrings, sanitize, dedupe.
- **Frontend:** DashboardPage.test.tsx — Action Needed card options/shares rows from mock API, deep-link URL with tab + accordion; SymbolDiagnosticsPage tests for accordion from URL.
