# R26.0 — Portfolio-Aware Position Sizing (Wheel: CSP/CC + Shares)

## Scope

Convert "ENTRY allowed/blocked" into "ENTRY sized to comply": reduce contracts/shares to the max allowable under guardrails; if max is 0, suppress ENTRY with safe reason codes. Expose sizing rationale in request-time details (structured fields only). Manual execution only; no new strategies (no spreads/condors/butterflies).

## Non-negotiables

- **Decision artifacts code-only** — No prose/UI strings; no FAIL_/WARN_ persisted in decision_latest.json.
- **UI** — Never display raw FAIL/WARN words or codes; safe labels only.
- **Determinism** — Same snapshot inputs → same sizing outputs.
- **No broker automation** — Manual execution only.
- **Gates** — Backend pytest, frontend tests, frontend build pass; evidence in `out/verification/R26.0/notes.md` + UAT checklist.

## 1) Sizing engine (backend)

- **Module:** `app/core/portfolio/sizing_r260.py`
- **Functions:**
  - `compute_available_budget(snapshot, guardrails_config)` → cash_budget_usd (after MIN_CASH_RESERVE_PCT)
  - `max_symbol_budget(snapshot, guardrails_config, symbol)` → max_additional_notional_usd (MAX_NOTIONAL_PER_SYMBOL_PCT)
  - `size_shares_entry(price, max_additional_notional_usd)` → qty (int)
  - `size_csp_entry(underlying_price, strike, max_additional_notional_usd)` → contracts (int); notional proxy: strike * 100 * contracts
  - `size_cc_entry(current_shares_qty, contract_multiplier=100)` → contracts (int); capped by options position count guardrail
  - `apply_sizing(candidate, snapshot, guardrails)` → sized_candidate or blocked with safe reasons

## 2) Wiring

- Action Needed / opportunities: for shares ENTRY compute recommended_qty; for CSP compute recommended_contracts (strike notional); for CC compute contracts from covered shares.
- Respect MAX_OPEN_OPTIONS_POSITIONS / MAX_OPEN_SHARES_POSITIONS / MAX_SYMBOLS_EXPOSURE: if at cap, size=0 → suppress with reason.
- Request-time fields on ActionNeededItem: `recommended_qty` (shares) or `recommended_contracts` (options), `recommended_notional_usd`, `sizing_constraints_hit` (safe codes), `sizing_recommended_by = "r260"`. No prose; safe short tokens only.

## 3) UI

- Dashboard Action Needed: show "Size: X shares" or "Size: Y contracts", "Notional: $…", "Constraints:" (safe labels).
- Symbol Diagnostics (Options/Shares): if ENTRY eligible, show "Suggested size" with same fields.
- Guardrails card: add "Available budget" (post-cash-reserve) and "Max add per symbol" when symbol available.

## 4) Tests

- Backend: `tests/test_r260_sizing.py` — available budget, symbol cap, CSP/CC sizing, action-needed sized/suppressed, no FAIL_/WARN_ in JSON.
- Frontend: Action Needed renders size/notional; no FAIL/WARN in DOM.
