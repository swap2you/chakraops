# R24.8 — Docker packaging baseline (backend + frontend)

**Date:** 2026-02

## Summary

Docker packaging added: backend and frontend each have a Dockerfile; docker-compose at repo root runs both with out/ bind-mounted. No auth or internet exposure in this release. Decision artifact semantics unchanged.

## What changed

- **chakraops/Dockerfile** — Python slim image; deps from requirements.txt; uvicorn on 0.0.0.0:8000. Build context repo root; workspace layout so canonical out/ path is /workspace/out.
- **frontend/Dockerfile** — Multi-stage: node build (npm ci, npm run build), then nginx or static server serving dist; expose 80 (mapped to 3000).
- **docker-compose.yml** — backend + frontend services; backend mounts ./out at /workspace/out, env_file .env (not committed); frontend depends_on backend; VITE_API_BASE_URL set for build.
- **.dockerignore** (chakraops, frontend, root) — Exclude out/, .venv/, node_modules/, dist/, __pycache__/, .env.
- **README** — Docker Quickstart, troubleshooting, state persistence note.
- **Env for frontend** — VITE_API_BASE_URL (build-time): set to http://localhost:8000 for docker-compose so browser calls backend on host port.

## Verification

- Gate outputs and UAT: out/verification/R24.8/notes.md.
- Requirements: chakraops/docs/releases/R24.8_requirements.md.

## Env vars (documented)

- **VITE_API_BASE_URL** (frontend, build-time): URL the browser uses to call the backend. For docker-compose set to `http://localhost:8000` (compose build arg in docker-compose.yml). For local dev with Vite proxy, leave unset to use relative `/api` and proxy to backend.
- **.env** (backend, runtime): Optional at repo root; use `env_file: .env` in compose. Not copied into images.

## Non-negotiables

- Decision artifact semantics unchanged; no prose in artifacts; no secrets in repo/images; gates recorded.
