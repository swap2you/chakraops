# R24.9 — Internet-safe deployment baseline (HTTPS + basic auth + same-origin routing)

**Date:** 2026-02

## Summary

Production deployment profile added: Caddy reverse proxy, same-origin API routing (/api proxied to backend), optional HTTPS (Let's Encrypt when DOMAIN set), and basic auth. Dev profile unchanged for local debugging. No secrets in repo or images.

## What changed

- **docker-compose.yml** — Profiles `dev` (default) and `prod`. Dev: backend 8000, frontend 3000, `VITE_API_BASE_URL=http://localhost:8000`. Prod: Caddy 80/443, backend and frontend internal only; frontend built with empty `VITE_API_BASE_URL` for same-origin /api.
- **Caddy** — New service (prod): reverse proxy `/` → frontend, `/api/*` → backend; basic auth from env (BASIC_AUTH_USER, BASIC_AUTH_HASH); optional TLS when DOMAIN set. Caddyfile + entrypoint to inject env into config (Caddy limitation with env in basicauth).
- **Security** — Backend CORS configurable via UI_CORS_ORIGINS; prod uses same-origin so strict origins. All traffic behind Caddy basic auth in prod.
- **README** — Production (VM) Quickstart, how to generate Caddy password hash, ports 80/443 only in prod.
- **Verification** — out/verification/R24.9/notes.md with gate outputs and UAT.

## Env vars (server .env only; not committed)

- **DOMAIN** — Optional. If set, Caddy obtains TLS (Let's Encrypt) for this domain.
- **BASIC_AUTH_USER** — Username for HTTP basic auth (prod).
- **BASIC_AUTH_HASH** — bcrypt hash from `caddy hash-password`; store in .env on server.
- **ORATS_API_TOKEN**, **SLACK_***, etc. — Unchanged; runtime env_file only.

## Non-negotiables

- No secrets in repo or images; UI safe labels unchanged; decision artifact semantics unchanged; gates recorded.
