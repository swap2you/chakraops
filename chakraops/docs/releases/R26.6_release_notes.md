# R26.6 — Data retention + backups for data/ (ops hardening)

## Summary

Backup and restore for `data/` (journal, checklists, monthly reports), optional retention cleanup for `data/reports/`, and Docker/README updates so `data/` and `out/` are clearly persisted. No change to decision artifacts or UI semantics.

## Changes

- **scripts/backup_data.sh** — Archives `./data` to `./backups/data_<timestamp>.tar.gz`; env `DATA_DIR`, `BACKUP_DIR`, `BACKUP_KEEP_N` (default 14); retains last N.
- **scripts/restore_data.sh** — Restores a backup into `DATA_DIR`; checks (file exists, target is dir); `--force` to overwrite; reminds to stop app/containers.
- **scripts/cleanup_reports.sh** — Keeps last `REPORTS_KEEP_N` months (default 24) under `data/reports`; removes older month folders; deterministic.
- **Docker** — Backend service: bind mount `./data` → `/workspace/chakraops/data` so journal/checklists/reports persist.
- **README** — State persistence: `out/` and `data/` must be persisted; backup/restore for data; no secrets in images.
- **.gitignore** — `data/` added so DBs and reports are not committed.
- **Tests** — test_r265_monthly_close_pack already covers base path override; optional test_r266_data_path_configurable if needed.

## Behavior

- Backup excludes only explicitly listed ephemeral patterns (if any); otherwise archives full `data/`.
- Restore refuses if `DATA_DIR` is not a directory unless `--force`; always prints “stop app/containers before restore”.
- Cleanup sorts month dirs (YYYY-MM), keeps last N, deletes older; dry-run or execute.

## How to test

1. Run `./scripts/backup_data.sh` → backup under `backups/`.
2. Run `./scripts/cleanup_reports.sh` (dry-run or on sample) → keeps last N.
3. Restore to a temp dir (or documented procedure).
4. Docker compose up → backend sees `data/` mounted.
5. Grep: no secrets or new tracked artifacts under `data/`.
