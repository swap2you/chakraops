# Release R28.3 — Notifications safe labels

**Date:** 2026-03  
**Branch:** release/R28.3  
**Goal:** Harden notifications so UI-facing data and UI never leak raw FAIL/WARN/PASS; persist and return only safe severity/labels; backward-compatible read.

---

## What changed

### Backend

- **app/core/notifications/notification_safe_labels.py** (new):
  - `normalize_notification_severity(raw)` → (safe_severity, safe_label): INFO→(Low, Info), WARN→(Medium, Advisory), CRITICAL/ERROR/FAIL→(High, Review), PASS→(Low, OK).
  - `normalize_notification_status(raw)` for optional status field.
  - `sanitize_message_for_api(msg)` replaces \\b(FAIL|WARN|PASS)\\b in message for API response.

- **notifications_store.py**:
  - `append_notification`: normalizes severity before persist; writes `severity` (safe) and `severity_label` only (no raw WARN/FAIL/PASS in file).
  - `load_notifications`: `_normalize_rec_for_api(rec)` normalizes legacy severity, adds severity_label, sanitizes message before appending to returned list. API payload never contains raw tokens.

### Frontend

- **UiNotification**: added `severity_label` (optional).
- **NotificationsPage**: severity column uses `gateStatusToLabel(severity_label ?? severity)` so raw values never displayed.
- **safeLabels.ts**: `sanitizeMessageForDisplay` now also replaces \\bPASS\\b with "OK".

### Tests

- **test_r283_notifications_safe_labels.py**: append persists no raw tokens; FAIL severity persists as safe; load normalizes legacy WARN; no decision_latest write; API response contains no forbidden tokens; normalize helper.
- **NotificationsPage.test.tsx**: mock uses safe payload; R28.3 test with legacy-style severity asserts no FAIL/WARN/PASS in DOM; R25.4 extended to include PASS.

## Backward compatibility

- Legacy notifications.jsonl lines with `severity: "WARN"` (or FAIL/PASS) are normalized at load time; API returns safe `severity` and `severity_label`; message is sanitized for API. Existing state machine (NEW/ACKED/ARCHIVED), dedupe, and ordering unchanged.
