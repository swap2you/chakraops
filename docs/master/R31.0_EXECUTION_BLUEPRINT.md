# R31.0 — Execution Blueprint for R32–R35

_Program R31–R35 · Milestone R31.0 output. This blueprint translates the baseline audit and defect register into file-level targets for the downstream milestones. R32–R35 packets must copy the exact paths from the relevant section below into their "Allowed tracked paths" before any source edit. This blueprint does not expand the locked program non-goals (no auto-trading, no broker routing, no silent fallback, no public hosting, no schema/scheduler/broker work without explicit operator approval)._

## How to use this document

1. Each milestone section lists candidate source files, candidate tests, and the defect IDs (from `R31.0_DEFECT_AND_GAP_REGISTER.md`) it closes.
2. Before a milestone starts, the writing agent copies the confirmed file paths into that milestone's `RELEASE_PACKET.md` Allowed-paths block, then implements only those.
3. Items marked **[APPROVAL]** require explicit operator approval because they touch AGENTS.md "Forbidden Unless Explicitly Approved" areas (schema migrations, new schedulers, history rewrite) or financial behavior.

## Cross-cutting constraints (all milestones)

- ORATS is the sole active options provider; any non-ORATS calendar/earnings source must be operator-approved, labeled, and never a silent options-data fallback.
- Manual-only trading; no broker routing; "stay in cash" is valid.
- Run the three AGENTS.md baseline gates after each milestone with evidence under `out/verification/<Release>/`; never report PASS without evidence.
- Level 4 (R32, R33) and Level 3 (R34, R35) require Claude Code architecture review + Codex independent review + operator approval before the final PR.
- **[APPROVAL]** gates (schema migrations, new schedulers, deployment/hosting, history scrub, broker work) must be explicitly approved by the operator before implementation; absent approval, the milestone stops at that boundary.

## Sequencing and stop conditions

R32 → R33 → R34 → R35, each starting only when the prior milestone is green (gates + evidence + reviewer verdicts) and its dependency (prior approved output) is satisfied. R32 additionally requires the operator-approved R31.0 defect register and this blueprint, plus resolution of dependency gap D-1 (R30.8 disposition).
