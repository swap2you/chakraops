# R25.9 — Portfolio Guardrails + Sizing Caps (Advisory-First, No Gambling)

## Scope

Portfolio guardrails and sizing caps: configurable limits (open options/shares positions, symbol exposure, notional per symbol, cash reserve, options risk per trade, sector exposure advisory). Request-time evaluation from account snapshot (holdings + tracked positions + cash). Hard caps block ENTRY from Action Needed with safe reason codes; sector is advisory-only. Dashboard and System Diagnostics show a Guardrails card with metrics and status (OK/Advisory/Blocked). Manual execution only; no broker automation.

## Non-negotiables

- **Decision artifacts code-only** — No prose/UI strings; no FAIL_/WARN_ persisted in decision_latest.json.
- **UI** — Never display raw FAIL/WARN words or codes; safe labels only (e.g. Passed, Degraded, Blocked).
- **Determinism** — Same snapshot inputs → same guardrail decisions.
- **Manual execution only** — No broker automation.
- **Gates** — Backend pytest, frontend tests, frontend build pass; evidence in `out/verification/R25.9/notes.md` + UAT checklist.

## 1) Guardrails config (defaults conservative; user can tune later)

- **MAX_OPEN_OPTIONS_POSITIONS** (default 6)
- **MAX_OPEN_SHARES_POSITIONS** (default 10)
- **MAX_SYMBOLS_EXPOSURE** (default 12)
- **MAX_NOTIONAL_PER_SYMBOL_PCT** (default 15) — shares + options notional
- **MIN_CASH_RESERVE_PCT** (default 25) — keep cash unallocated
- **OPTIONS_MAX_RISK_PER_TRADE_PCT** (default 2) — sizing cap when sizing exists
- **SECTOR_EXPOSURE_ADVISORY_PCT** (default 35) — advisory only (not a block)

Config in a single place (e.g. app/core/settings.py or config module); `get_guardrails_config()` returns a dict.

## 2) Guardrails evaluation (request-time, deterministic)

- Compute portfolio utilization from current account snapshot (holdings + tracked positions + cash).
- Determine if a new ENTRY recommendation would violate caps.
- **Violations (hard):** Do not recommend ENTRY; set safe “Blocked by guardrail” reason codes in request-time details. Suppress ENTRY from Action Needed.
- **Advisory-only (sector):** Show “Advisory” flag; do not block.

## 3) Surfaces

- **Dashboard:** “Guardrails” card — cash reserve %, open options count, open shares count, symbols exposure count, max symbol notional %; status: OK / Advisory / Blocked (safe labels).
- **Action Needed / Opportunities:** Suppress ENTRY suggestions that violate hard caps; show safe reason (e.g. “Cash reserve rule”, “Max open positions reached”).
- **System Diagnostics:** Guardrails block with same metrics + status.

## 4) Tests

- **Backend:** Deterministic guardrails decisions; enforcement prevents ENTRY in action-needed when caps violated; advisory-only sector does not block; API payload contains no FAIL_/WARN_ substrings (including word-boundary FAIL/WARN).
- **Frontend:** Guardrails card renders; safe labels only; no FAIL/WARN in DOM text.
