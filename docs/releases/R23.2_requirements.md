# R23.2 — Delta Transparency + Near-Miss + Optional Delta Override (Advanced) + Gate Code Persistence

## Objectives

- Persist gates as code-only (gate_code); no "name" or prose in decision JSON.
- Delta reject transparency: show best_delta, miss, direction (BELOW_BAND/ABOVE_BAND), best_candidate.
- Near-miss: when rejected due to delta and miss ≤ DELTA_NEAR_MISS_EPS, add DELTA_NEAR_MISS to primary_reason_codes (code-only).
- Optional per-symbol delta override (advanced): chakraops/data/delta_overrides.json; bounded by DELTA_OVERRIDE_MAX_WIDEN; API GET/POST/DELETE; UI "Adjust delta band (Advanced)" and "Override active" badge.

## Scope

### Part 1 — Gate code persistence (code-only)

- to_dict_persist: gates output gate_code + status only (no name, no reason).
- from_dict: backward compat — if old file has "name", map to gate_code; new format has gate_code.
- API: translate gate_code → safe English label at request time only.

### Part 2 — Delta transparency (request-time only)

- symbol-diagnostics includes delta_diagnostics when Stage 2 delta rejects: band_min, band_max, best_delta, miss, direction (BELOW_BAND/ABOVE_BAND), best_candidate (strike, expiry, bid, ask, spread_pct).
- UI: "Delta band (rejected)" card with band, best_delta, miss, direction as safe text, best candidate row.

### Part 3 — Near-miss + override (advanced)

- Config: DELTA_NEAR_MISS_EPS (0.02), DELTA_OVERRIDE_MAX_WIDEN (0.05).
- When REJECTED_DUE_TO_DELTA and miss ≤ EPS → add DELTA_NEAR_MISS to primary_reason_codes (code-only); verdict unchanged.
- Override file: chakraops/data/delta_overrides.json (NOT under out/). Per symbol: delta_lo, delta_hi, updated_at_utc. Bounded by max_widen.
- API: GET /api/ui/delta-overrides, POST /api/ui/delta-overrides/{symbol}, DELETE /api/ui/delta-overrides/{symbol}.
- UI: "Adjust delta band (Advanced)" when Show Advanced; "Override active" badge when override present.

### Part 4 — Tests and docs

- Backend: gate_code in persisted gates (no "name"); delta_diagnostics direction; override boundaries; overrides not in decision JSON.
- Frontend: delta_diagnostics card; advanced gating; no raw FAIL_/WARN_.
- R23.2_requirements.md, R23.2_release_notes.md, RELEASE_CHECKLIST.md, out/verification/R23.2/notes.md with gate outputs and UAT.

## Non-goals

- Decision JSON remains code-only; no prose, no delta_override in artifact.
- Override does not auto-ELIGIBLE; only widens Stage-2 delta band check.

## Acceptance criteria

- [ ] Persisted gates have gate_code (^[A-Z0-9_]+$), no "name" field.
- [ ] WMT (or delta reject) shows best_delta, miss, direction (below/above band), best candidate.
- [ ] Override within max_widen works; exceeding rejected; override not in decision_latest.json.
- [ ] UI: Override active badge; Adjust delta band only when Show Advanced.

## UAT checklist

- WMT delta reject shows best_delta + miss on Symbol page.
- Set override for WMT within allowed band → override works; badge "Override active".
- Delete override → baseline behavior; no badge.
- grep decision_latest.json: no "name" in gates; no FAIL_/WARN_ prose.

## Rollback

- Revert R23.2 commits. delta_overrides.json is optional; remove or leave. No migration.
