# R24.0 — Actionable Notifications + Options Position Sizing + Position-Aware Alerts

## Non-negotiables

- Decision artifacts remain code-only. No persisting prose/UI strings. No raw FAIL_/WARN_ in persisted JSON.
- UI must never display raw FAIL_/WARN_ codes.
- SDLC gate: backend pytest, frontend tests, frontend build — all recorded in `out/verification/R24.0/notes.md`.
- Repo hygiene: no new out/ artifacts unless whitelisted in RELEASE_CHECKLIST; no secrets.

## Part A — Options position sizing (request-time only)

- **A1** Add `options_sizing` to `GET /api/ui/symbol-diagnostics?symbol=...` (request-time only, never persisted).
  - If symbol has a selected option candidate (CSP or CC), compute suggested contracts using conservative cash-secured sizing.
  - Use account equity/available_cash from GET /api/ui/accounts/default or account summary path.
  - Config: `OPTIONS_RISK_PCT_PER_TRADE_DEFAULT`, `OPTIONS_MAX_CONTRACTS_PER_TRADE`, `OPTIONS_MAX_NOTIONAL_PCT` (e.g. in trade_rules.py).
  - CSP: required_cash = strike * 100 * contracts; credit_est = mid or bid * 100 * contracts.
  - CC: contracts limited by floor(shares/100); required_cash=0; credit_est similarly.
  - Return shape: basis (OK | INSUFFICIENT_DATA | NO_SELECTED_CANDIDATE), suggested_contracts, required_cash, credit_estimate, risk_pct_used, notes_codes (codes only).
- **A2** Frontend Symbol Diagnostics Options tab (Trade accordion): show Suggested contracts, Required cash, Credit estimate, Risk % used. If basis != OK, show compact safe message (no raw codes).

## Part B — Actionable Slack notifications

- **B1** Notification builder: per-symbol actionable messages when eligible for option trade (contract identity, delta, bid/ask, credit estimate, suggested contracts, required cash, top 2 reasons as safe labels); delta near-miss (best_delta, miss, target band); position target/stop/invalidation hit when tracked positions exist.
- **B2** Throttling/dedupe: same alert type for same symbol at most once per N minutes (config); critical alerts (stop/invalidation) exempt.
- **B3** Slack messages never contain FAIL_/WARN_ or secrets.

## Part C — Position-aware next action (request-time only)

- **C1** Add `next_action_code` (ENTRY | HOLD | CLOSE | ROLL | REDUCE | NONE) to symbol-diagnostics. ENTRY when eligible and no current position in that strategy; CLOSE when stop/invalidation or target hit suggests exit; HOLD otherwise.
- **C2** Small badge in Symbol header showing next action.

## Part D — Dashboard “Action Needed”

- **D1** Dashboard card: top 3 actions for options and top 3 for shares; from universe + shares candidates + tracked positions. Each row links to symbol page with tab + accordion anchor.

## Part E — Testing + docs + verification

- **E1** Backend: tests/test_r240_options_sizing.py (CSP/CC sizing, insufficient data, sizing not persisted); tests/test_r240_slack_actionable_messages.py (required fields, no FAIL_/WARN_/api_key/token).
- **E2** Frontend: options sizing block and Action Needed card tests.
- **E3** Docs: R24.0_requirements.md, R24.0_release_notes.md, out/verification/R24.0/notes.md (gate outputs + UAT checklist), RELEASE_CHECKLIST R24.0 section.
