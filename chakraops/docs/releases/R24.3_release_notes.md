# R24.3 — Position-Aware Lifecycle Alerts for Tracked Option Positions + wheel_state Retention

**Date:** 2026-02

## What changed

- **Request-time lifecycle for tracked option positions:** New module computes pct_max_profit, dte, mark_proxy, assignment_risk (bool + reason fields), roll_window (bool + fields), recommended_action_code (CLOSE/ROLL/HOLD), recommended_by "r243". Inputs: position entry credit, mark proxy, expiry, strike, spot, DTE. Rules: PROFIT_TARGET_HIT → CLOSE; ROLL_WINDOW (low DTE) → ROLL/CLOSE; ASSIGNMENT_RISK (ITM, low extrinsic) → CLOSE/ROLL. All outputs request-time only; never persisted to decision_latest.json.

- **API:** GET `/api/ui/action-needed` options items may include lifecycle fields from tracked positions (pct_max_profit, mark_proxy, assignment_risk, roll_window, recommended_action_code). No FAIL_/WARN_ in response.

- **Slack:** Actionable message includes pct_max_profit and action when available; symbol/strategy/exp/strike/dte unchanged. No raw codes.

- **Dashboard:** Action Needed shows lifecycle details (safe text); severity ordering unchanged.

- **wheel_state retention:** Per-symbol cap on `linked_position_ids` (WHEEL_STATE_LINKED_POSITION_IDS_MAX, default 50). When saving state, trim to last N IDs per symbol. Documented in CLEANUP_POLICY.md. Tests enforce retention.

## Endpoints

- **GET /api/ui/action-needed** — Options items may include `pct_max_profit`, `mark_proxy`, `assignment_risk`, `roll_window`, `recommended_action_code` (from R24.3 position lifecycle when applicable). Backward compatible.

## wheel_state retention

- **Rule:** Keep at most `WHEEL_STATE_LINKED_POSITION_IDS_MAX` (env, default 50) linked_position_ids per symbol. When writing wheel_state (repair or state_machine), trim each symbol's list to the last N IDs. Prevents unbounded growth from repeated OPEN/CLOSE/ROLL.
- **Doc:** CLEANUP_POLICY.md § wheel_state retention.
