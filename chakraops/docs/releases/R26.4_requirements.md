# R26.4 — EOD routine + weekly review automation (checklists + reminder notifications)

## Scope

Checklist persistence (EOD / Weekly), APIs for eod-summary and weekly-summary, Today EOD section and Weekly Review page, in-app reminder notifications at 19:00 ET (EOD) and Sunday 19:00 ET (weekly). Manual-only; no broker automation.

## Non-negotiables

- Decision artifacts code-only; no prose/UI strings; no raw FAIL_/WARN_ in decision_latest.json.
- UI safe labels only; no raw FAIL/WARN.
- Determinism: checklist state from stored rows + journal data only.
- No broker automation.
- Gates + evidence in out/verification/R26.4/notes.md + UAT.

## 1) Checklist persistence (SQLite under data/)

- Table: checklist_state (id, kind "EOD"|"WEEKLY", key date YYYY-MM-DD / week YYYY-WW, status "OPEN"|"DONE", done_ts, notes).
- Store: app/core/ops/checklist_store_r264.py (init/migrations, get/set/list).

## 2) API

- GET /api/ui/ops/checklist?kind=&key=
- POST /api/ui/ops/checklist/mark-done (kind, key, notes?)
- GET /api/ui/ops/eod-summary?date=YYYY-MM-DD (eval as_of, action_needed_count, notifications_new_count, journal_entries_count_for_date).
- GET /api/ui/ops/weekly-summary?week=YYYY-WW (realized P/L from journal, trade counts, winners/losers, guardrails snapshot).

## 3) Frontend

- TodayPage: End of Day Checklist section (counts from eod-summary, Mark EOD Done).
- WeeklyReviewPage: weekly-summary + checklist, Mark Weekly Done.
- Banners: "EOD checklist pending" on Today; same on Weekly when pending.

## 4) Reminder notifications (in-app)

- 19:00 ET: if EOD for today not DONE → OPS_EOD_CHECKLIST_REMINDER (dedupe per date).
- Sunday 19:00 ET: if weekly for current week not DONE → OPS_WEEKLY_REVIEW_REMINDER (dedupe per week).
- Dedupe: one per key while NEW or ACKED exists (R25.4-style).

## 5) Tests

- Backend: test_r264_ops_checklists.py (mark done, reminder dedupe, weekly summary from journal, no FAIL_/WARN_ in JSON).
- Frontend: TodayPage EOD section, WeeklyReviewPage, mark done mocks, no FAIL/WARN in DOM.
