# R26.6 — Data retention + backups for data/ (journal/checklists/reports)

## Scope

Ops hardening: backup and restore scripts for `data/` (journal DBs, checklists, monthly reports), retention policy for `data/reports/`, and Docker/README guidance so `data/` and `out/` are persisted. No decision artifact or UI semantics changes.

## Non-negotiables

- No secrets committed.
- `out/` remains gitignored; `data/` remains gitignored for DBs and generated reports.
- Do not change decision artifact semantics.
- UI safe labels rule unchanged.
- Gates + evidence in out/verification/R26.6/notes.md + UAT.

## 1) Backup scripts (scripts/)

- **scripts/backup_data.sh**
  - Archives `./data` to `./backups/data_<YYYYMMDD_HHMMSS>.tar.gz`.
  - Excludes ephemeral caches (allow/deny list).
  - Retains last `BACKUP_KEEP_N` (default 14); deletes older.
  - Env: `DATA_DIR=./data`, `BACKUP_DIR=./backups`, `BACKUP_KEEP_N=14`.

- **scripts/restore_data.sh**
  - Restores a specified backup tar.gz into `DATA_DIR` (default `./data`).
  - Safety: confirm backup exists; refuse if `DATA_DIR` is not a directory; optional `--force` to overwrite.
  - Print steps: stop containers/app before restore.

## 2) Retention for data/reports

- Document: keep last N monthly packs (default 24 months) or allow infinite if small.
- **scripts/cleanup_reports.sh**
  - Keeps last `REPORTS_KEEP_N` months (default 24).
  - Deletes older month folders under `data/reports`.
  - Deterministic, safe.

## 3) Docker guidance

- README: `./data` and `./out` must be persisted (host/volume).
- Compose: add bind mount for `./data` to backend (e.g. `/workspace/chakraops/data`).
- No secrets in images.

## 4) Tests

- Backend: unit test for monthly_close_store base path override (configurable path, no hardcoded OS paths).
- Scripts: shellcheck-friendly; no heavy testing.
