# R23.4 — Ticker Copilot v1 (read-only, evidence-grounded Q&A)

## Objectives

- Add a read-only Copilot panel on the Symbol page for natural-language questions about the current ticker and system state.
- Answers must be grounded in ChakraOps API data and allowlisted docs only; no hallucinations; no writes/mutations.
- Decision artifacts remain code-only and untouched; no copilot output persisted.

## Scope

### Part A — Backend: Copilot endpoint (POST /api/ui/copilot/ask)

- Request: symbol, question (required), conversation_id (optional), mode (symbol | general).
- Response: answer_markdown, citations, followups, used_tools, snapshot_used, request_id.
- Server-side OpenAI (Chat Completions with tools); model from COPILOT_OPENAI_MODEL env (default gpt-4o).
- Tools (read-only): get_symbol_diagnostics, get_decision_latest, get_universe_row, get_positions_tracked, get_account_default, get_account_holdings, get_share_position, get_delta_override, get_system_health, search_docs.
- Output safety: post-processor rejects FAIL_*, WARN_*, api key, token, internal paths; replaces with safe message.
- Curated docs: search_docs limited to allowlisted .md files (releases, RELEASE_CHECKLIST, phase_22 doc).

### Part B — Frontend: Copilot panel on Symbol page

- Right-side panel when symbol is loaded: input, send, message list (user + assistant), loading/error states.
- Default prompt chips: "Why is this symbol not eligible?", "What delta missed the band?", "Support/resistance?", "Position/holdings exposure?", "Is data fresh?".
- Safe markdown rendering; Copy answer button.
- conversation_id stable per symbol (e.g. copilot-{symbol}).

### Part C — Tests

- Backend: test_r234_copilot_contract.py (200 with mocked OpenAI, tool allowlist only), test_r234_copilot_safety.py (forbidden patterns replaced), test_r234_docs_search_allowlist.py (allowlist only).
- Frontend: CopilotPanel.test.tsx (renders, chips send request, answer and copy shown).

### Part D — Docs and verification

- R23.4_requirements.md, R23.4_release_notes.md, RELEASE_CHECKLIST.md R23.4 section, out/verification/R23.4/notes.md with gate outputs and UAT checklist.

## Non-goals

- No order placement, no overrides/holdings/account writes from copilot.
- No persistence of copilot answers into decision_*.json.
- No exposure of API keys or secrets to frontend (OpenAI calls server-side only).

## Acceptance criteria

- POST /api/ui/copilot/ask returns 200 with answer_markdown, citations, followups, used_tools.
- Only read-only tools are exposed; no write endpoints.
- If model output contains FAIL_/WARN_/token/api key, response is replaced by safe message.
- search_docs returns only allowlisted files.
- Symbol page shows Copilot panel with chips and input; answer rendered safely; Copy answer works.
- No decision artifact files modified by copilot usage.

## Security model

- OpenAI API key used only on server (OPENAI_API_KEY); never sent to frontend.
- UI auth (x-ui-key) required for POST /api/ui/copilot/ask same as other UI routes.
- Tool implementations call internal Python only; no arbitrary file read; docs allowlist only.

## UAT checklist

- Copilot answers "Why not eligible?" and cites tools used.
- Copilot answers delta miss for a symbol using delta_diagnostics.
- Copilot refuses to answer if asked for secrets (e.g. "what's the ORATS token?") — safe replacement message.
- No state changes: verify no POST/DELETE besides /copilot/ask from copilot flow; no decision artifact files changed.

## Rollback

- Revert R23.4 commits; remove openai from requirements if unused elsewhere. No data migration.
