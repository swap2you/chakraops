# Release R27.9 — Unified Positions DB v1

**Date:** 2026-02  
**Branch:** release/R27.9  
**Goal:** Read-only aggregation of positions from live shares, live options, and paper into a unified list; safe labels only.

---

## Scope summary

- **Backend:** SQLite store schema (positions_open, positions_closed) under data/positions.db; read-only builder aggregating holdings_db, share_positions, tracked positions store, paper store; **API:** GET `/api/ui/positions/unified` with query params `state`, `include_paper`, `instrument_type`, `symbol`; system-health block `positions_unified` (open_count, closed_count, last_build_ts).
- **Frontend:** New **Positions** page at **/positions** (user-visible): filters Open/Closed, Live/Paper, Type (Shares/CSP/CC), Symbol; columns Symbol, Type, Qty, Opened, Mark/Unrealized (if available), Ticket link, Journal link.
- **Determinism and safe labels:** Unified list has stable ordering (symbol, type, expiry, strike, opened_ts) and stable IDs; responses and UI use safe labels only (no raw FAIL_/WARN_ in API or DOM).
- **Tests:** Backend deterministic ordering, filters, no FAIL_/WARN_ in payloads; frontend no FAIL/WARN in document.
