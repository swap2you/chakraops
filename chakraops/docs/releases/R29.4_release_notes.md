# Release R29.4 — Integrity Check details/history + System Diagnostics parity

**Date:** 2026-03  
**NO GIT.** Manual-only.

**Goal:** Expose last integrity check details (summary + sample items) and optional history; parity on System Diagnostics. No new sources-of-truth; deterministic; safe labels only.

---

## User-visible changes

- **Positions page — Integrity strip:** Last integrity check shows status, timestamp, and counts (missing/extra/mismatched). "View details" toggles sample items list (kind, symbol, instrument_type, id, fields_diff). "View full diff in Diagnostics" link to /system. Run integrity check button unchanged.
- **System Diagnostics:** New card "Unified Positions Integrity Check" with same summary (status, last run time, counts), "View details" toggle for sample items, "Run integrity check" button, and link to Positions.

## API

- **GET /api/ui/positions/unified/integrity-check** — Read-only. Returns `{ status, status_label, last: { status, status_label, started_at_utc, finished_at_utc, missing_count, extra_count, mismatched_count, sample_items }, history: [...] }`. History capped (e.g. 10); deterministic ordering.
- **State file:** `out/positions_unified_integrity_check_state.json` — last run + history; safe fields only; no forbidden tokens.
- **System-health:** Block `positions_unified_integrity_check` includes last_started_at_utc, last_sample_items (optional).

## Sanitization

- Shared UI helper `sanitizeForDisplay()`: replaces/blocks raw PASS/FAIL/WARN and strips FAIL_/WARN_. Used for all integrity-check strings and fields_diff.
