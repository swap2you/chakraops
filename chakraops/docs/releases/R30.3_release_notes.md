# Release R30.3 — Attach readiness pack to Journal/Ticket (manual, sanitized, deterministic)

**Date:** 2026-02  
**NO GIT.** Manual-only.

**Goal:** Allow operator to optionally attach a sanitized readiness pack (JSON bundle) to a journal entry when saving from Trade Ticket, and download it from the Journal UI. Stored in SQLite (data/); no decision write.

---

## User-visible changes

- **Trade Ticket — Journal draft:** New checkbox **"Attach readiness pack to journal entry"** (default off). When checked and the user clicks "Save to Journal", the created entry stores an attached readiness pack (same sanitized JSON as the R30.2 ZIP contents: manifest, readiness, system_health_subset, notes).
- **Journal page:** For entries that have an attached readiness pack, a **"Download readiness pack"** link/button appears in the Pack column. Clicking downloads the JSON file as `readiness_pack_<symbol>_<entry_id>.json`.

## API / backend

- **POST /api/ui/journal/from-ticket:** Request body may include **attach_readiness_pack** (boolean, default false) and **mode** (live|paper). When attach_readiness_pack is true, a sanitized readiness pack bundle is stored in journal_attachments (SQLite).
- **GET /api/ui/journal/entry/{entry_id}/attachment/readiness-pack:** Returns the attached JSON bundle (application/json). 404 with safe message if no attachment.
- **GET /api/ui/journal:** List response entries now include **has_readiness_pack** (boolean).
- New table **journal_attachments** (id, journal_entry_id, kind, content_json, created_at_utc). No decision_latest write.

## Tests and evidence

- Backend: test_r303_journal_readiness_pack_attachment.py — attach persists sanitized JSON; download returns same; no forbidden tokens; no decision write; attach false creates no attachment.
- Frontend: TradeTicketPage — checkbox and payload; JournalPage — download button when attachment exists; no forbidden tokens.
