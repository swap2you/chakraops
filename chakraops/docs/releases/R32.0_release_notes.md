# R32.0 Release Notes — Market Data, Earnings, Universe, Freshness (COMPLETE)

_Program R31–R35, milestone 2 on `release/R31-R35-program`._

## Summary

R32.0 makes market inputs observable, fresh, and failure-classified. It delivers the Critical security remediation (C-1, environment-only ORATS token), resolves Claude's non-blocking notes (consumer migration to `get_orats_token()`; runtime.yaml token field removed; missing-token startup test), and implements the full data-reliability scope: freshness + stale-data blocking, deterministic weekly universe refresh with auditable history, explicit event/earnings calendar availability, and provider-health/cache/retry/rate-limit/failure-classification visibility with read-only ORATS contract validation. ORATS remains the sole provider; there is no silent fallback.

## Delivered (C-1)

- `chakraops/app/core/config/orats_secrets.py`: removed hardcoded token; environment-only resolution; added `get_orats_token(required=False)` that fails loudly (no value leaked) when a required token is missing. `ORATS_API_TOKEN` module attribute retained (env-resolved) for backward compatibility and test patches.
- `chakraops/app/api/server.py`: startup reads token from env; logs a redacted presence boolean; warns loudly when missing; ORATS boot probe reports `UNAVAILABLE` (not a fake `OK`) when the token is absent.
- Fixed misleading "hardcoded" wording in `scripts/orats_smoke.py` and `README.md`.
- Verified `.gitignore` ignores `.env`/`*.env`; `.env.example` placeholder present (no real value).
- Added `tests/test_r320_orats_secret_env_only.py` (6 tests).

## Delivered (Claude non-blocking notes)

- Migrated runtime token consumers from the import-time `ORATS_API_TOKEN` constant to `get_orats_token()` (orats_client, orats_opra, orats_equity_quote, orats_chain_pipeline, cc_chain_v2, csp_chain_v2, evaluation_service_v2, evaluation_store_v2, orats_daily_provider, ui_routes). `get_orats_token()` honors the module attribute, preserving existing test patches.
- Removed the `api_token` field from `config/runtime.yaml` so no literal placeholder can be read as a credential.
- Added `tests/test_r320_missing_token_startup.py` (fail-loud startup/provider state, no fallback).

## Delivered (R32.0 data-reliability scope)

- `app/core/data_reliability/freshness.py`: freshness timestamps + `stale_data_gate` that blocks actionable output when required inputs are STALE/MISSING (M-10).
- `app/core/universe/weekly_refresh.py` + `refresh_history_store.py`: deterministic weekly universe (sorted, dedup, overrides) with stable reason codes and append-only JSONL refresh history — **no database migration** (M-4).
- `app/core/data_reliability/event_calendar_status.py`: explicit AVAILABLE/UNAVAILABLE state for macro and earnings calendars (H-4); an empty stub result is never read as a confident "no events".
- `app/core/data_reliability/provider_health.py`: provider-health snapshot (token presence only), cache policy, retry/backoff + rate-limit surfacing, provider-failure classification, and read-only ORATS contract validation (GET-only, no order/broker endpoints).
- `app/api/data_reliability_routes.py` (read-only, under `/api/ui`) + `frontend/src/api/queries.ts`/`types.ts` read-only query contract.
